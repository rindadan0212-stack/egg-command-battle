# 絵の描き方（`pixel` / `paint` / `icon` 共通）

✅ **実装しました**（2026-08-29・icon の実寸目録を追加して統一）。

## ルールは1つだけ

> 🔴 **1ドット＝設計 4px。絵は必ず「実ドット数 × 4」で置く。引き伸ばさない。**

`pixel`（種族の絵）・`paint`（背景・器）・`icon`（小物・状態異常）の3種類とも、
これ1本の規則で描かれる。骨組みの節点の幅・高さは、**その絵の実ドット数 × 4** に
すること。合っていなければ `LayoutDom.FitDotsStyle` が黙って伸縮させたりはみ出させたり
せず、位置だけ中央寄せして**実寸のまま**置く（＝見た目が壊れる）。

## 手順

1. **描く**（実ドット数のまま。4倍や8倍に拡大した PNG を書き出さない）
2. `assets/ui/icon/` または `assets/ui/paint/` に置く（`pixel` は `art/sprites/` 系・別経路）
3. **目録を作り直す道具を走らせる**（`game/` から打つ）
   ```
   dotnet run --project EggCommand.Sim -- icon-manifest       # icon の実寸目録
   dotnet run --project EggCommand.Sim -- paint-placeholder   # paint の実寸目録（仮置きも作る）
   ```
4. `dotnet test` を通す

## ⚠️ 落とし穴

- **整数倍で書き出す。** `paint`/`pixel` の PNG は「1 ファイル画素＝1 ドット」（拡大しない）。
  骨組み側が × 4 して置く。
- **目録を作り直す道具を忘れると、`dotnet test` が黙って古いまま緑になる**わけではない ──
  `ManifestFreshnessTests` が実物の PNG と目録を突き合わせて落とす。落ちたら道具を走らせる。
- **枠と絵の大きさが合わないと `dotnet test` が落ちる**（`PicFrameSizeTests`）。
  骨組み（`assets/layouts/*.txt`）の幅・高さを、目録の実寸 × 4 に直すこと。

## 🔴 流れる背景（ホームの空・山・遠くの地面）は、道具に組ませる

背景の帯だけは**手で置かない**。⭐ 作者の絵を `assets/ui/home-src/` に置いて
`node tools/bg-band.mjs` を走らせると、**繋がるように並べ直した PNG** を
`assets/ui/paint/home-*.png` に書き、`home.txt` に写す行と `stage.css` の動きを刷ってくれる。

> 🔴 **帯は「元・鏡・元・鏡」の4枚。2枚ぶん流して先頭へ戻す。**

⚠️ **2枚（元・鏡）で1枚ぶん流すのでは駄目**（2026-08-29 まではそうなっていた）。
流し終わりに映っているのは「鏡」なので、先頭へ戻る瞬間に**画面全体が左右反転してパッと
切り替わる**（実測: 山の帯で 1080×252 の全画素が入れ替わっていた）。
4枚並べて2枚ぶん流すと、模様の周期（元＋鏡）と流す距離が一致し、**流し終わりの画面が
流し始めと1画素も違わない**。

⭐ この絵は**作者のドット密度のままでなくてよい**（`shrink=` で間引く）── ゲームのドットより
細かく描かれていることが多く、等倍だと「遠くの木」が画面幅の85%になったりする。
手前の層ほど速く動かす（空12 → 山24 → 遠くの地面48 px/秒）。

⚠️ 3か所（絵の枚数・骨組みの幅・意匠の流す距離）が食い違うと輪が開く。
`StageCssTests.流れる背景は輪が閉じている` が突き合わせて落とす ── **静止画では絶対に
捕まらない不具合**なので、この検査を消さないこと。

## 🔴 `icon` だけ特別な事情がある（読んでから描くこと）

`icon`（`assets/ui/icon/*.png`）は歴史的事情で、**ファイルの実ピクセル数がそのままドット数
にならない**（`paint`/`pixel` と違う）。実測（2026-08-29・ブロック検出）:

| 名前 | ファイルの実ピクセル | 目録の実ドット数 |
|---|---|---|
| 状態異常16種（`status-*`）| 128×128px（実物12枚）／32×32px（未着手4枚）| **16×16 固定** |
| それ以外（`arrow`/`die`系/`goal`/`locked`/`mob`/`plain`/`stat-*`）| 128×128px | 128÷4＝32×32 |

`status-*` の16種類は同じ枠（戦闘の状態異常アイコン `unit.txt`・`sicon`）に並ぶので、
**目録は家族で大きさを揃えてある**（`EggCommand.Sim/IconManifestTool.cs` の
`DotsOf` にルールと理由が書いてある）。**新しく `status-` で始まる icon を描くときは、
16×16 ドットで描くこと**（＝ 64×64px でそのまま書き出しても、`icon-manifest` を走らせれば
目録は自動で 16×16 に揃う ── 特別扱いはツール側で吸収される）。

`status-` 以外の新しい icon は、素直に「実ドット数のまま書き出す → `icon-manifest` が
実ピクセル÷4を記録する」で足りる。

## ⚠️ いま中身が無い4枚

`status-seal` / `status-anchor` / `status-invincible` / `status-counter` は、
`PaintPlaceholder`（`sim paint-placeholder`）が自動で作った**仮置きの単色四角**のまま
── **まだ描かれていない。** 16×16 ドットで実物を描き、
`assets/ui/icon/` の同名 PNG を上書きしたあと `sim icon-manifest` を走らせること。
