# 画面をドット絵で組む（pixelizer → 骨組み）

✅ **実装しました**（2026-08-25）。`sim import-screen <.pixelizer.json>`。

## 0. なぜ

> 今いろいろおいてある状態を編集するより **0 から置いていく方が作りやすそう**。
> ピクセライザーに画面比率と画素数を揃えたキャンバスを作って、
> そこで**比率を確認しながら**アセットを作れるようにしたい。 ── 作者（2026-08-25）

⭐ いまのエディタ（`/edit`）は「既にある骨組みを直す」道具として作った（E1・E2）。
⚠️ **0 から画面を起こす**には、先に「どこに何をどれくらいの大きさで置くか」を
決める場所が要る ── それは絵を描く場所と同じであるべき。

## 1. 🔴 実測した土台 ── **変換が1回も要らない**

| | 実測（2026-08-25） |
|---|---|
| 画面 | **270×480 ドット**（9:16）。1ドット＝設計 4px ＝ 1080×1920 |
| `paint` の PNG | 🔴 **1px ＝ 1ドット**（`frame-dock` は 270×58px、manifest も `270 58`）|
| 骨組みの座標 | **ドット × 4**（`mats paint 0 0 1080 80` ↔ `home-mats.png` が 270×20）|
| pixelizer の 1× 書き出し | 等倍・補間なし（`imageSmoothingEnabled=false`）|
| pixelizer のレイヤーの重なり | **配列の末尾が手前**（実測）── 骨組みと**同じ向き** |

⭐ **pixelizer の等倍書き出しと `paint` の 1px=1ドットが元から一致している。**
⭐ **重なりの向きも一致している。**だから間に変換を挟まない。

⚠️ `icon` だけは 4px=1ドット（128×128px ＝ 32ドット）で例外。⭐ ここでは `icon` を作らない
（アイコンの描き直しは[ドット絵化計画](ドット絵化計画.md) §8-3 の別件）。

### `.pixelizer.json` に入っているもの（実測）

```
{ v, w, h, currentLayer, currentFrame, color, palette,
  layers: [ { name, opacity, visible, frames: [ dataURL(等倍PNG) ] } ] }
```

🔴 **必要なものが全部入っている**（キャンバスの寸法・レイヤー名・等倍の絵）。
⭐ だから **pixelizer にゲームの知識を1つも入れずに**繋げられる。

## 3. 流れ

```
pixelizer（270×480 のキャンバス）
  レイヤー「home-mats」    ← 背景の帯を描く
  レイヤー「slot-frame」   ← 孵化器の枠を描く
  レイヤー「_exp」         ← 数字が入る場所（目安・絵にしない）
  レイヤー「_tap-trial」   ← 押しどころ（絵は要らない・場所だけ）
        ↓  「そのほか」→ ファイルに書き出す（.pixelizer.json）
        ↓  art/screens/home.pixelizer.json  として版管理に入れる
  sim import-screen art/screens/home.pixelizer.json
        ↓
assets/ui/paint/home-mats.png    ← レイヤーを bbox で切り出し（等倍のまま）
assets/ui/paint/slot-frame.png
assets/layouts/home.txt（雛形）   ← 座標 = bbox × 4
```

⭐ **`.pixelizer.json` は版管理に入れる**（`art/screens/`）── 画面の**設計の出所**が
リポジトリに残る。⚠️ localStorage はブラウザの「閲覧データを削除」で消える
（pixelizer の README 自身がそう警告している）。

## 4. レイヤーの約束（**ゲーム側だけが知る**）

| レイヤー名 | 何が出るか | 骨組みに出る行 |
|---|---|---|
| `home-mats` | `assets/ui/paint/home-mats.png`（bbox で切り出し） | `mats paint <左> <上> <幅> <高> pic=home-mats` |
| `_tap-trial` | 🔴 **PNG は出さない** | `trial button <左> <上> <幅> <高>`（`tap=` は空 ── エディタで選ぶ）|
| `_exp` | 🔴 **PNG は出さない** | `exp label <左> <上> <幅> <高> text=exp`（仮の字 ── 後で直す）|
| `Layer 3`（名前を付け忘れ） | ⚠️ **何も出さない。警告する** | ── |

⚠️ **`_` は「絵にしない」の印**。⭐ 字・数・キャラは骨組みが描くので、
絵にすると**二重に出る**（下に焼き付いた字と、上に載る本物の字）。

⚠️ **中身が全部透明なレイヤーは飛ばして警告する**（黙って 0×0 を出さない）。

⭐ 骨組みの並びは **pixelizer のレイヤー順のまま**（末尾が手前・§1 で実測）。

---

## 5. 座標の作り方

1. レイヤーの**透明でない範囲**（bounding box）をドット単位で求める
2. 骨組みの座標 ＝ **bbox × 4**

⭐ ドット単位で切るので、**座標は自動的に4の倍数になる**
（[ドット絵化計画](ドット絵化計画.md) §2 の升目の規則を、計算の形で満たす）。

⚠️ **枠と絵は必ず一致する**（幅 = bbox幅 × 4）── 段取り4 で 44箇所も出た
「枠と絵が合わない」が、この経路では**原理的に起きない**。

## 6. 測った性能（2026-08-25・実測）

| | 72×128（今の最大） | **270×480** |
|---|---|---|
| 合成1回 | 0.09ms | **1.04ms** ⭐ 60fps に余裕 |
| 取り消し1回の複製 | 0.1ms | 0.7ms ⭐ |
| 取り消し1回のメモリ | 0.21MB | **2.97MB** |
| 取り消し **50回**ぶん（`MAX_UNDO`） | 10.5MB | 🔴 **148MB** |

⭐ **速さは問題ない。**⚠️ **メモリだけが問題。**
`snapshotState()` が「変えていないレイヤーまで丸ごと複製する」ため、
面積が 14 倍になるとそのまま 14 倍になる。

## 7. 決めたこと（続き）

### 7-1. ✅ **PC だけで描く**（作者・2026-08-25）

⭐ だから `MAX_UNDO` は今のまま。148MB は 32GB の PC で問題にならない。
⚠️ **iPad・スマホでこのキャンバスを開くとタブが落ちうる**（他のキャンバスは今までどおり）。
そちらでも描きたくなったら、取り消しの持ち方を変える（案は下記）:
- **(a) 枚数でなく容量で上限を決める**（例: 合計 64MB まで）── 単純・汎用的
- **(b) 変わったレイヤーだけ複製する** ── 1回 0.5MB になるが、構造変更の巻き戻しを別に持つ必要がある

### 7-2. 目安は `_tap-`（押しどころ）と `_`（字の場所）の2つだけ

⚠️ `pixel`・`icon`・`bar` の目安はまだ無い。⭐ **足りないと分かってから足す**
（印を増やすほど覚えることが増える）。

### 7-3. 既にある画面は上書きしない

`sim import-screen` は既存の `assets/layouts/<名前>.txt` を**1バイトも書き換えない**。
座標を並べて出すだけなので、合わせたい行だけ手で直すかエディタで動かす。
⭐ 絵（`paint/*.png`）のほうは上書きするが、**大きさが変わったら警告する**。

## 8. 使い方

```
# 1. pixelizer で 270×480 を選んで描く
#    `絵を描く.bat` → 「サイズと変換」→「たて長のサイズ」→「9:16 画面まるごと」→ 270×480
# 2. 「そのほか」→ ファイルに書き出す → art/screens/<画面名>.pixelizer.json に置く
# 3. 取り込む（game/ から打つ）
cd game
dotnet run --project EggCommand.Sim -- import-screen art/screens/home.pixelizer.json
dotnet run --project EggCommand.Sim -- paint-placeholder   # 絵の一覧を作り直す
# 4. エディタで tap= と text= を決める
```

⚠️ **`sim import-screen` は `Scenes.All` を増やさない。**新しい画面を足したら
`game/EggCommand.Web/Scenes.cs` にも1行足すこと（`ScenesTests` が数の食い違いで落ちる）。

## 9. 検査（`ImportScreenTests`・7件）

| 何を守るか | |
|---|---|
| 🔴 出した骨組みが**読めて往復も閉じる** | `Write(Parse(x)) == x`・不備ゼロ |
| 座標はドット×4 ＝ **必ず4の倍数** | ドット (18,154) 75×95 → `72 616 300 380`（実物の `home.txt` と一致）|
| 🔴 **絵は枠とぴったり同じ大きさ** | 段取り4 で 44箇所出た不一致が原理的に起きない証拠 |
| 目安と押しどころは**絵にしない** | `_exp.png` / `trial.png` を作らない |
| **既にある骨組みを書き換えない** | 手で書いた字が1バイトも変わらない |
| 大きさの違うキャンバスを断る | 座標が全部ずれた骨組みを作らせない |
| 名前を付け忘れたレイヤーを書き出さない | `Layer 2.png` を黙って作らない |

⚠️ **踏んだ罠**: 最初 `Console.SetOut` で出力を横取りしていたら、xUnit が組を並列で
走らせるので **`SheetRoundTripTests` の出力まで奪って**巻き添えで落ちた。
⭐ `ImportScreen.Run` は書き出し先（`TextWriter`）を受け取る形にして、グローバルを触らない。
