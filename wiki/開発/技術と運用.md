### 起動と停止

| やりたいこと | コマンド |
|---|---|
| 遊ぶ | **`ゲームを開く.bat`**（サーバー起動 → ブラウザ → **閉じたらサーバーも終了**） |
| 開発する | `npm run dev`（⚠️ こちらは自動で終了しない） |
| 確実に止める | `npm run stop` |

⭐ ブラウザを閉じたことの検出は **SSE 接続が切れること**で見る。
⚠️ **心拍のタイムアウトでは判定しない** — ブラウザは背面タブのタイマーを絞る・凍らせるので、
「一定時間申告が無い＝閉じた」は**開いているタブを殺す**（実際に踏んだ）。
再読込や画面移動でも接続は切れるので、猶予5秒を置いてから終了する。

### 決まりごと

- **乱数は種から。`Math.random()` 禁止。** 系統（stream）を分け、
  新しい乱数の使い手が増えても既存の系列がずれないようにする
- **ゲージと CT は整数単位**で進める（浮動小数のドリフトを持ち込まない）
- **強さの計算は唯一の出所を持つ。** ステ実値・ダメージ・ゲージ進行・CT 減衰は
  それぞれ1つの純粋関数に置き、戦闘・シミュレータ・UI が全部そこを呼ぶ

### 強さの測り方:算数を正とする（2026-08-19・作者の判断）

⚠️ **AI シミュレーションを「順位付け」に使わない。**

⭐ 作者の指摘 ──「勝ち負けで測るのもおかしくないか？ 勝つ条件は相手のHPを0にすることなので
アタッカー以外はそれでは測れない」。

⚠️ 勝率そのものは間違っていない（チーム戦なので壁役・回復役の貢献も勝率に乗る）。
**本当の欠陥は AI のほう**:

| 欠陥 | 実例 |
|---|---|
| **AI がプレイヤーの代理にならない** | 2026-08-19、AI の採点定数が古く **23技を一度も選ばなかった**。あのときその23技は「弱い」と測れていた |
| 試験編成が中立すぎる | 削られていない編成で回復を測っていた |
| 平均を測っている | [適材適所](#) の考え方と真逆 |

#### ⭐ 何を正とするか

| 順 | 何で判断するか |
|---|---|
| **1** | **算数**（`sim turnvalue`）── 1手で何手ぶんを生むか。AI もサイコロも通らない |
| **2** | **人が読んで判断**（作者の方針 2026-08-19）── 効果文を読めば強すぎ・弱すぎは概ね分かる |
| **3** | **人が遊んだ体感** ── 2026-08-19、`枠1ばかり撃っている` は体感が先に見つけた |
| 使わない | AI シミュレーションによる**順位** |

⭐ **シミュレーションは「壊れ検出」には使う**（繋がっていない特性・採用率0.00・桁の取り残し）。
2026-08-19 はそれで7件見つけている。⚠️ ただし「どちらが強いか」には使わない。

#### ⚠️ 算数と実戦が食い違ったら、そこを掘る

⭐ **実例（2026-08-19・掘った結果）**: 毒は算数で 1.44手ぶんなのに勝率では −0.1pt。
`sim delivered` で数えたら、**間に2つ挟まっていた**:

1. **持続を使い切れない** ── 4ターンのうち実際に削れたのは **2.1回**
2. **遅れて入るぶんは価値が下がる** ── 量では 1.13倍 入っているのに勝率は ±0。
   ⚠️ **直接ダメージは相手の手番を奪うが、後から効くものは奪わない**

⭐ **算数の側が間違っていた。**「持続 × 効果量」をそのまま足すと、
即座に確定する効果（ダメージ・回復・盾）と同じ土俵に並べてしまう。
`sim turnvalue` に `LateDiscount = 0.7` を入れて直した。

⚠️ **食い違いは「どちらが嘘か」ではなく「間に何が挟まっているか」**を見ること。

### 釣り合いの方針:適材適所（2026-08-19・作者の判断）

⭐ **総合勝率を 50% に揃えにいかない。**

> 種族によって得意不得意がありビルドも違うので、差が生まれるのは必然。
> 物には役割ってものがある。適材適所だ。 ── 作者

⚠️ 揃えにいくと、せっかく作った顔（キバネ＝止める / イワオ＝重い / ホムラ＝配る）が消える。
⚠️ 総合が 30% でも、3種族に勝ち越しているなら**それは役割**であって欠陥ではない。

#### ⭐ 代わりに見るもの

| 見るところ | 何が言えるか |
|---|---|
| **勝ち越す相手が 0** | どこにも居場所が無い ── **役割が無い** |
| **負け越す相手が 0** | 誰の役割も奪う ── **対策が存在しない** |

⭐ この2つだけが直し先。`sim species` が右2列に出す。

⚠️ **この考え方は種族に限らない。**技も特性もステも、「どれも同じ強さ」ではなく
**「どれかが刺さる場面を持っているか」**で見る。
⭐ `sim traits` が左右2列（噛み合う技／噛み合わない技）を出すのも同じ理由。

### 検査の方針（2026-08-19・作者の判断）

⚠️ **「値が正しいか」を検査しない。**「繋がっているか」と「帯に収まっているか」だけを見る。

⭐ 作者の指摘 ──「ゲームの数値はすべて計算で導かれるので、計算式さえ変えなければ、
増えたスキルを明らかに壊れた性能にしなければ大丈夫では」。**半分そのとおり**で、
コンテンツを足すときの検査はデータ表を書き写すだけになり、何も証明しない。

⚠️ **ただし、実際に壊れたのは「式」ではなく「式の外」だった**（2026-08-19・同じ日の4件）:

| 壊れたもの | 何が起きたか | 見つけたのは |
|---|---|---|
| `Idle.EnemyHp` | 桁上げで火力が5倍になり、敵が瞬殺されて**誰も倒れなくなった** | 検査 |
| `Steal.SpeedToDistance` | 飛距離が5倍になり、**誰でも一投で親に届く** | 検査 |
| `Ai` の価値8定数 | **23技の採用率が 0.00**（AI が一度も選ばない） | 実測（`sim skills`）|
| `TraitGritGauge` | 執念が想定の 1/20（+4.3pt / 本来 +17.5pt）| 実測（`sim traits`）|

⭐ 4件とも**計算式は1行も変えていない**。危険は式の中ではなく、
**別ファイルにあって式の出力と比べられる定数**（＝システムの継ぎ目）にある。

#### だから、こう配る

| | どうするか |
|---|---|
| **足さない** | 技・特性・種族の**内容**を書き写す検査。データ表の複製にしかならない |
| **残す** | ①ゴールデン（移植が正しいことの唯一の証拠・作り直せない）②保存の読み書きと引き継ぎ ③`Audit` 系（繋ぎ忘れ・入手不能の検出）④継ぎ目の検査 |
| **増やす** | **実測（`sim`）**。高くついたバグはどちらも実測でしか見つからなかった |

⚠️ **「明らかに壊れた性能」は目では判定できない。**
帯に収まっているかを言うには、収まっている範囲の実測が要る
（特性の初期値は紙の上では常識的だったが、実測で 先駆け +22.5pt / 粘り腰 +17.3pt と
既存の帯 +2〜19pt を外れ、下げた）。

⭐ 副次的に、検査は**変更の波及範囲**を教える。育成を作り替えたとき12件が落ち、
どこまで影響が届いたかが一覧で出た（自分で追うと確実に見落とす）。

## 9. 参考作品

### まものダンジョン＋ の進化スキル（2026-08-19 調査）

⚠️ **一次情報**: `mamodan-library.com`（まもダン図書館＋・非公式ファンサイト）。
WebFetch は 403 で弾かれるので、**実ブラウザ（Playwright）でないと読めない**。

#### 向こうの規模

効果 **145種類 / 584体**。分類は
強化状態20・強化効果10・弱化状態18・弱化効果10・ステータス制御13・
特殊エフェクト11・攻撃タイプ18・その他24・リーダースキル21。

⭐ **「その他24」がほぼ全部カウンタープレイ**（〜無視／〜貫通／〜封じ／〜無効）。
中に **「パッシブ・進化スキル封じ」19体**がある ── **特性を封じる層まである**。
⭐ **「ターン獲得」が独立した効果**で 68体（うち進化スキル 26体）。

#### 実物3つ（うちの特性と比べるための基準）

| スキル | 効果 |
|---|---|
| **台風の目**（スザク風）| 相手をスタンさせると自分のゲージ **+100%**。スタン状態の相手にターンが回った時、**別の相手に 30% でスタンが伝播** |
| **ペイオフ・イグニッション**（リリリア火）| 自ターン開始で **エナジー+2**、自分のスキル2『チャーム・アリュール』発動で **+3**（最大10）。1個につき速度 +3%（最大30%）。相手に免疫/バリア/継続回復が付いた時 **3個消費で全体解除**。相手がスタンでターン開始した時 **7個消費でゲージ +100% ＋ その相手の攻防 −35%（最大70%）** |
| **スタークラスター**（スターマン火）| 自分のスキル2の**攻撃回数 +1**、かつ **1発目の攻撃対象を選べるようになる** |

#### ⚠️ うちの特性との構造的な差（7軸）

| 軸 | まもダン | このゲーム（11件すべて）|
|---|---|---|
| 報酬の単位 | **手番**（ゲージ +100% ＝ 丸1ターン）| **割合**（12〜25%）。手番を生むのは 1/4 ターンが3件だけ |
| 条件の置き場所 | **盤面**（相手がスタン／相手に免疫が付いた）＝**相手の状態変化を購読** | **自分の内側**（HP半分以下・盾が剥がれた）。盤面を見るのは追い打ちだけ |
| 資源 | **固有リソースを生成・消費**（エナジー・虎魂・印・カートリッジ…）。貯める／使うの判断が生まれる | **無し** |
| 技との結びつき | **自分の技を名指しで書き換える**（「シューティングスターの攻撃回数 +1」）| 技を一切知らない |
| 操作の幅 | **プレイヤーの権限が増える**（「1発目の対象を選べるようになる」）| 数値だけ。権限は増えない |
| 対抗手段 | **進化スキル封じ**がある | 特性に触れる手段が1つも無い |
| 連鎖 | 発動が**次の発動条件を自分で作る**（スタン→ゲージ→行動→スタン）| 発動しても盤面は変わらない |

#### ⭐ 一言でいうと

**向こうの進化スキルは「その個体を中心に戦い方を1つ設計させるエンジン」。
うちの特性は「決まった戦い方に後から乗る補正」。**

⚠️ 実測がこれを裏付けている ── `sim traits` で
先駆け・粘り腰・背水は「噛み合わない技でも同じだけ伸びる」（＝技を選んでいない＝計画に入っていない）。

⚠️ **規模を真似る話ではない**（584体 対 8種族）。真似るのは**形**:
①手番を報酬にする ②条件を盤面に置く ③資源を持たせる ④技を名指しする ⑤操作の幅を変える。

### ⭐ 種族を1つ足す手順（ここだけ見ればいい）

1. `Species.cs` の `List` に**1行**足す（id・名前・枠1の技・基礎値・ドット絵・パレット・卵ガチャ）
   ⚠️ 属性は書かない（個体が持つ）。⚠️ 巣に立てるなら `Encounters.Pool` にも足す
2. `dotnet test` … 中身の数える検査（`Content.Audit`）が繋がりを見る
3. `dotnet run --project EggCommand.Sim -- species skills` … 総合勝率が 35〜65% に入るか、死んだ技が出ていないか
4. **`図鑑を開く.bat`** … 一覧で見て、偏りや抜けを目で確かめる


### 📖 図鑑（`図鑑を開く.bat` / `sim book`）

⭐ Core の表から毎回**書き出す**ので、表を直せば図鑑もその場で変わる。
⚠️ 手で書いた一覧は必ず古くなるので作らない。`図鑑.html` は書き出したものなので直さない（gitignore）。

| 節 | 見えるもの |
|---|---|
| 種族 | ドット絵・枠1が何で伸びるか・基礎値4本・卵ガチャのプール・巣に立つか |
| 技 | 効果の内訳・確率・CT・対象と、⭐ **どの種族から出るかの逆引き** |
| 素質 | 働く場面・すること・**噛み合うもの** |

⭐ 逆引きが主役。目で数えるのが一番つらい情報で、**空欄＝手に入らない技**がひと目で分かる。

⚠️ **id は永久**。あとから改名・削除しない（どうしても要るときは `Migrations` に1行足す。元の行は消さない）。
⚠️ 既にある4種の**卵ガチャのプールは凍結**。乱数で引く対象なので、足すと照合がまとめて落ちる。
新しい技は**新しい種族のプールへ**入れる。
