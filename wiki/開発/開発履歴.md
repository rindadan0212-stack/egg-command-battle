### 起動と停止（ユーザー要望）

- **`ゲームを開く.bat` を追加。** サーバー起動 → ブラウザ →
  **ブラウザを閉じるとサーバーも終了**する。中身は ASCII のみ・CRLF
  （日本語を書くと cmd.exe が黙って失敗するため）
- **`npm run stop` を追加。** ⚠️ Windows では npm の親を止めても
  vite の子が孤児として残る（罠と教訓 §5）。ポートを握っている PID を落とす
- **判定は SSE 接続が切れることで行う。**

  | 案 | 採否 | 理由 |
  |---|---|---|
  | **SSE 接続が切れたら終了** | **採用** | タブを閉じてもブラウザが落ちても即座に切れる。背面に回っただけでは切れない |
  | 心拍のタイムアウト | 不採用 | ブラウザが背面タブのタイマーを絞る・凍らせるので、**開いているタブを殺す**（§4 で実際に踏んだ形） |
  | `pagehide` の sendBeacon | 不採用 | ブラウザが強制終了したときに飛ばない。SSE なら TCP が切れるので拾える |

- 実測: 画面移動（index→gallery）では**落ちない**（猶予5秒）／
  ブラウザを閉じると**5秒以内に終了**しポート解放／
  `npm run dev` 単体は `autoClose: false` でブラウザ無しでも稼働継続

### 段B: 戦闘（3v3・スピードゲージ + CT）

**数値は1つも勘で置いていない。** すべて `npm run sim` に当てて決めた。

#### 種族を1種→3種へ前倒し（段E の作業）

⚠️ タマルの種族スキル「殻打ち」が**防御スケール**なので、1種族しか無いと
**防御が「守り」と「攻め」を兼ねて**釣り合いの計測が丸ごと濁る。
測れない以上、段Bを正直に終われないので前倒しした。
属性3すくみも1種族では検証不能だった。

| 種族 | 属性 | スキル1 | 基礎値（合計は全種80） |
|---|---|---|---|
| タマル | 鱗 | 殻打ち（防御スケール） | 24/18/22/16 |
| ツノガ | 牙 | 強撃（攻撃スケール・単体） | 22/24/18/16 |
| ハネル | 羽 | 薙ぎ（攻撃スケール・全体） | 20/18/16/26 |

#### 較正の記録（何を測って何を決めたか）

| 決めたもの | 値 | 決め方 |
|---|---|---|
| `HP_SCALE` | 3 | 「1体を倒すのに5〜12発」で掃引。実測 9〜15発 |
| `GAUGE_BASE` | 55 | 速度一強の検算。0 だと速度型の勝率 **100%** |
| `ATK_SOFTEN` / `DEF_SOFTEN` | 20 / 110 | 2次元掃引（atk 0〜40 × def 40〜220） |

⭐ **速度一強は実在した。** 素の速度でゲージを埋める形だと勝率100%。
速度は「行動回数」＝**全出力への倍率**で上限が無いのに、
ダメージ側は式で頭打ちになっていたため。基礎テンポを足して比を圧縮した。

⭐ **防御が攻撃の約3倍の価値を持つ**ことが分かった。3v3 の集中攻撃では
狙われた1体が毎ラウンド3発受けるので、防御は3回効き攻撃は1発にしか効かない。
だから `DEF_SOFTEN` を `ATK_SOFTEN` より大きく取っている（対称に置くと防御編成が85%）。

#### 途中で見つけた設計の穴

1. ⚠️ **ダメージ式が特化を構造的に無意味にしていた**（罠と教訓 §8）。
   `2a/(a+d)` は比だけで決まるので、攻撃特化が防御特化を殴っても均等どうしと同じ。
   → `(A+a)/(D+d)` に変更
2. ⚠️ **「壁」という役割に実体が無かった**（罠と教訓 §10）。
   耐久型は自分が死なないだけで味方を守れず、脆い火力役が真っ先に落ちていた。
   → **「かばう」を追加**。役割分担編成 23.3% → **50.7%**（かばう無しは 20.1%）
3. ⚠️ **AI が回復を過大評価**していた。「HPを18戻す」と「敵のHPを8削る」を
   素点で比べると回復が常に勝ち、1体落とすのに62行動かかっていた。
   → 不足分と緊急度で割り引く

#### 決めたこと

- **戦闘に乱数を入れない**（命中率も会心も無い）。
  ⭐ こうすると「1万回の勝率」が**個体差の分布**を測ることになり、検算が濁らない
- **通常攻撃は枠を消費せず誰でも使える**。無いと全スキルが CT 中のとき手が無くなる
- **`MAX_ACTIONS = 300` で打ち切り**。回復役どうしは理論上終わらないので、
  条件で塞がず上限で守る

#### 残した課題

⚠️ **均等ぞろい編成が依然80%で最強**（課題.md「調整」）。着手時より27ポイント改善したが、
「弱点が無いこと」が「得意が2つあること」に勝っている状態は解けていない。
数値目標は作業の指針であって合否ではないので、**輪が閉じてから遊んで決める**（段F）。

### 段D: 配合と遺伝

未決を2件決着させた。

| 項目 | 決定 | 根拠 |
|---|---|---|
| 変異と合計上限 | **変異1回で 1ステ上限+1 / 合計上限+2**（20回まで＝60/120） | 変異の +2 が素の上限で即削られると価値が消える。⭐ **常に2倍の比を保つ**ので「得意を2つ作れる」がどの変異段階でも崩れない |
| 育成ポイント | **勝つと +1・上限20・振り直し不可** | もらえるのは出撃した個体だけ＝「連れ出す」が育成に直結。上限があるので時間で素質差を埋められない |

#### ⭐ ARK の変異確率の正体が分かった

公表値 7.31% / 0.184% / 0.00156% は、**2.5% を3回振る**と完全に一致する。

```
1回以上   = 1 - 0.975³         = 7.314%
ちょうど2 = 3 × 0.025² × 0.975 = 0.183%
ちょうど3 = 0.025³             = 0.00156%
```

個別に確率を置くより素直で、**値が食い違う余地が無い**。

#### 実測

| 対象 | 実測 | 狙い |
|---|---|---|
| 高いほうの親から取る | **55.03%** | 55% |
| 変異 1回以上 | **7.3192%** | 7.31% |
| 変異 ちょうど2回 | **0.1867%** | 0.184% |
| 変異 ちょうど3回 | **0.0013%** | 0.00156% |
| カウンタ上限のブレーキ | **0/50,000** | 変異しない |
| 空振り検査（片方が20未満） | 7.49% で変異 | ブレーキが本物 |
| 上限の比（変異0〜30） | **常に 2.0倍** | 崩れない |
| 20世代の血統（毎世代10卵から最良） | 素質 80→**90** / 変異 0→5 | 世代で伸びる |
| 配合の卵を孵して技が引き直された | **0件** | 狙って引いた技が消えない |

⚠️ **設計上の食い違いを1つ見つけて直した。**
卵は「スキルは孵化時にガチャ」で作っていたが、それだと**配合で狙って引いた技を
孵化時に引き直してしまう**。卵に「技が決まっているか」の欄を足し、
野生の卵は `null`（ガチャ）／配合の卵は決定済み、と分けた。

⭐ **`npm run sim -- --progress` を作った。** 初期パーティから始めて巣を回し、

#### 足したもの

- **4種族目「ヌシ」**（ボス専用・鱗）と **震撼**（CT7 の全体大技）

- ⭐ **対象選択**（単体攻撃で狙う相手を選べる）

#### ⚠️ 輪は最初、閉じていなかった

`--progress` を回したら **14周してもボス勝率 0%**。しかも**ボス本体に与えた総ダメージが 0**。
ここから4つの別々の原因が出てきた。

| 見つけたもの | 直し方 |
|---|---|
| ⭐ **単体攻撃の対象が自動で「残HP最少」だったので、HPが最も高いボスは眷属が全滅するまで一度も狙われない** | プレイヤーが対象を選べるようにした（罠 §14） |
| ボスが素質120（変異20）で、プレイヤーは素質80で頭打ち。変異は7.31%でしか出ないので届かない | 変異4（素質62）まで下げた |
| 眷属2体が両方とも回復役で持久戦になり、素質120のパーティでも186HPに11ダメージしか通らなかった | 回復役を1体も置かない編成に |
| 敵の総HPがパーティの出せる総ダメージを超えていた | 総HPを 387 → 335 に |

⚠️ さらに**測る側のミスが2回**あった（罠 §15）。素質120のつもりのテスト編成が実際は80だったこと、
「鱗に有利なのは牙」と自分の表を読み違えたこと。
⭐ **同じ数字が2回出たら、まず測り方を疑う。**

#### 結果

```
⭐ 10 周目で 淵のヌシ に勝率50%以上 → 100%
   最終戦 46行動 / 勝利 / 敵の残HP 0 · 0 · 0
```

**輪は閉じている。**

⚠️ ただし `--progress` の方針は素朴（属性を散らして各種族の最良を1体ずつ）。
最初これを「素質合計の上位3体」にしていたら**同種ばかりになってボス勝率が永久に0%**だった。
⭐ **この game が要求しているのは合計ではなく編成**、というのが数字で出た。

#### 巣の難易度は段位順ではない

実測で **段4(17%) が段5(100%) より難しい**。3すくみが効いているため
（鱗パーティは牙の巣を圧倒し、鱗の巣に勝てない）。
⚠️ 段位＝難易度と読めないので、遊ぶ人が混乱しないか段F で見る。

## 2026-08-16（続き）: スキル体系とゲージの作り直し

まもダンを調査（`参考/まもダン_スキル調査.md`）した結果を受けて改修。

### 変えたこと

| 変更 | 理由 |
|---|---|
| ⭐ **同時に満ちたら「内部ゲージが多い者」が動く** | 以前は配列の並び順。根拠が無く、**繰り越した超過ゲージが一切報われていなかった**（まもダン準拠） |
| ⭐ **`ct` プリミティブを追加**（猛り / 絡み） | **CT が本作の戦闘の芯なのに、それを操作する手が1つも無かった** |
| **枠1（種族固定）は CT なし** | 「たたかう」の役目を兼ねる。全スキルが CT 中でも手が無くならない |
| **「たたかう」を廃止** | 枠1が兼ねるので不要。スキルは3つだけになった |
| ⭐ **威力を「小・中・大・特大」の段位に** | 独立した数値が「技の数」から**4つの定数**に減り、較正が表1つで済む |
| **速度の数値表示を廃止** | ゲージの伸び方で読ませる |
| ⭐ **ゲージをリアルタイム更新** | ⚠️ **状態は決定論のまま**。実時間で進むのは**見た目だけ**（棒の幅のみ更新し、DOM は作り直さない） |

| 先攻側の勝率 | 53.2% | ⭐ **51.1%** |
| 編成の最強と最弱の差 | 60pt | ⭐ **41pt** |

| 輪が閉じる周回 | 10周目 | ⭐ **7周目** |

⭐ **課題に上げていた「1戦102行動と長い」が 42行動まで縮んだ。**

だから同じ総量でも単体のほうが強い。これが手数を割り引く理由。

**踏んだ罠を3件記録**（25: cascade で `display` が打ち消されていた / 26: `space-between` が
空きが負でトラックを重ねた / 27: 「絵以外の高さ」を推測して倍率表を書いた）。

**検査に重なり判定を追加**。はみ出し検査は枠の外しか見ておらず、枠の中の重なりを
一切捕まえられなかった。足した直後に本物を1件検出。
