## 6-1. 計画（着手前）

### ⚠️ web で新しく生まれる消失経路は、退避（eviction）ではない

| | なぜ Unity には無かったか |
|---|---|
| **同じゲームを2つのタブで開ける** | Unity は1プロセス。両方が20秒ごとに書いて**後勝ちで片方が消える** |
| **閉じる瞬間に書き込みが間に合わない** | IndexedDB は非同期。`pagehide` 中の完了保証がない |

⭐ 対策（**機能ではなく保存の一部として最初に作る**）:
- Web Locks か `BroadcastChannel` で**書き手を1タブに限る**。2枚目は読み取り専用
- `visibilitychange`/`pagehide` では **localStorage の写しを同期で更新**。起動時に新しいほうを採る

### 層

```
層3  ブラウザの外 : 書き出したファイル        ← ⭐ 本命
層2  localStorage : 同じ JSON を1本（同期）   ← 閉じる瞬間の保険
層1  IndexedDB    : 世代リング + persist()   ← 主
```

⚠️ 層1と層2は Safari では**同じカウンタで一緒に消えます**。ブラウザ内に「別の消え方をする場所」は事実上ありません。**ここが Unity との本質的な差**で、だから層3が本命です。

⭐ **10世代持っても 110KB。**圧縮も差分も要りません。世代は「直近／5分前／1時間前／1日前／1週間前」で間引くと、「少しずつ壊れていく」形にも耐えます。

### 🔴 #7 が難しい理由

書き戻し器は**行番号で位置を固定**する。削除（行が消える）・追加（末尾に足す）は既に安全だが、
**並べ替え・親子付け替え**は「節点は元の行位置のまま描かれる」ので木で動かしても字は動かない。
⭐ 正しくやるには Core に**行番号の振り直し**か**まるごと再直列化する書き出しモード**が要る。
だからここだけ段階を分ける。

### 背骨 ── 「属性表」（`Art`/`Scenes`/`Beats` と同じ唯一の出所）

```
属性表 = 付け足しごとに1行:
  key（size/ink/anchor/text/…）／型（数・切替・選択肢・字・色）
  ／効く種類（labelだけ・iconだけ…）／日本語ラベル／安全な範囲
```

⭐ Inspector はこの表から**自動で欄を生む**。編集できる属性を増やす＝**表に1行**
（`ApplyLeft/Top/…` のような専用メソッドを増やさない）。表は Core の `Options`/`Kinds` から
派生させ、**ずれない**ようにする。

⚠️ **コマンドオブジェクトへの作り替えはしない。**骨組みは1枚100行未満で、いまの
**snapshot undo（木ごと文字列で積む）で十分**かつ単純 ── 定石が言う「save-less／infinite undo」
の利点は snapshot でも得ている。過剰な抽象化を避ける方針どおり、**土台は今のまま**伸ばす。

これに伴い2点だけ一般化:

| いま | これから |
|---|---|
| 選択＝`_selectedLine`（int 1つ）| **選択＝行番号の集合**（＋Inspector用の主たる1つ）|

| 3 | 削除・追加・複製（種類のパレット）＋色（`ink=`）編集 | 不要 |
| 4 | 並べ替え・親子付け替え（木のドラッグ）＋新規ファイル作成 | **要**（行番号の振り直し）|

### 事実（Core の `Layouts.Write` を読んで確定 ── 推測でない）

  「末尾＝新ルート」の位置で盤に出る。

### 🔴 先に潰した罠3つ
| 罠 | 実態 | 対策 |

### ② 押した部品への自動ジャンプ・逆向き

`edit.js` に、掴んで動かす用の `nodeAt`（`_partId` で縛る・既存のまま不変）とは**別**に、
タップで選ぶときだけ使う `pickAt` を足した:

```js
el.closest('[data-part],[data-line]')
```

⭐ **近い方（DOM で内側）を優先する 1 行だけ**で、モード分岐が要らない。理由:
`Layouts.Splice` は差した部品の中身を「差した節点の**子**」として組むので、
`data-part` を持つ子孫は必ず `data-line` を持つ祖先より内側にいる。

| 見つかったもの | 何が起きるか |
|---|---|
| `data-part="X"` | `PickedPart(X, partLine)` を呼ぶ。`X == _of` なら**ただの選び直し**、
  違えば**部品 X のファイルへ切り替えて**その行を選ぶ |
| `data-line=N`（`data-part` が無い） | `Picked(N)` を呼ぶ。C# 側は
  `Scenes.Of(_of).ByPart` を見る ── `use=` で差し込まれる9部品は自分の内容が
  必ず `data-part` になる（`data-line` では絶対に拾えない）ので、「`ByPart` な
  文書を開いているのに `data-line` で拾えた」＝**土台の行**と確定できる。
  この場合は土台（`HostId`）へ切り替えて選ぶ（②の逆向き） |

⚠️ **`down()`/`move()`（掴んで動かす）は触っていない。**もし `pickAt` と同じ「近い方優先」を
掴んで動かす側にも使うと、部品が乗った領域を掴んでドラッグしたとき「土台の節点をまとめて
動かす」という**既存の**（今回壊していない）挙動が失われる（part 側の節点は今の文書に無いので
ドラッグが無反応になる）。**タップ選択と、掴んで動かすは、別の探し方でよい**
（前者は「今すぐ切り替えても構わない」・後者は「切り替えると掴んだ節点を見失う」ため）。

**未保存の直しの扱い**: 盤の上のタップ切り替えだけ、`IsDirty`
（`Layouts.Write(_raw) != _originalText` ── Undo 積みの有無では判定しない。保存しても
積みは捨てない作りなので「積みがある＝未保存」は誤り）を見て `window.confirm` で1度だけ確かめる
（`eggEdit.confirmDiscard`）。⚠️ **ドロップダウン（`OnOfChange`）は確かめない**（今までどおり
即切り替え ── 「動いているものをついでに作り替えない」の指示どおり、新しい一手にだけ足した）。

## 11-2. ✅ `repeat=` の `gap` を掴む ── 解けた（2026-08-24）

### ⚠️ 長らく解けなかった理由: 「縦にも効く」と思い込んでいた

`Layouts.StepOf` の署名（`gap` を読む分岐が存在する）だけを見て、「`gap` は縦横どちらにも
効きうるので、1つの複製を動かすと2方向の要求がぶつかる」と考えていた。⭐ **実物を数えずに
コードの分岐の存在だけで「起きうる」と判じたのが誤り。** 実際に実物41箇所（`repeat=` の
出現）を洗うと、`cols>=2` で複数段になる骨組みは**必ず** `rows=` を明示しており、
`StepOf` は `rows=` があればそれを返して `gap` を一度も見ない。`rows=` が無い6箇所は
すべて `max==cols`（1段しかない）。⭐ **つまり「縦にも効く」場面は実物に1つも無い** ──
揉める2方向ではなく、**常に横1方向だけの数**だった。

もう1つ、「列0は `gap` の影響を受けない」を**2つ目の例外**と読んでいたのも誤り。
これは例外ではなく、**「左端の列が並び全体の錨・それ以外の列が間隔を決める」という
1つの規則**として言える（`LayoutDom.One`: `left = node.Left + (i % cols) * (node.Width + gap)`
── `col==0` の項は常に `node.Left`、`col>=1` の項だけが `gap` を含む）。

### ⭐ 規則（実装した形）

| 掴んだもの | 変わる数 |
|---|---|
| **0列目**の複製を横へ（`k % cols == 0`） | `左`（並び全体が動く。今までどおり） |
| **1列目以降**を横へ（`k % cols >= 1`） | ⭐ `gap` ── `_repeatBaseGap + dx / (k % cols)` |
| どの複製でも**縦へ** | `上`（並び全体）。🔴 **`gap` は触らない**（縦は `rows=` の領分） |

⚠️ **`rows=` を掴んで変えるのは今回やっていない**（決めた理由）: `rows=` が無い行に
新しく足すと「無かった欄を足す」処理（`BuildSlots` の新顔＝行末に追加）になり、
既存の `gap=`（横）とは書き出しの経路が違う。今回は「`gap` を掴む」1点に絞り、
縦の間隔を数値で直したいときは Inspector の欄（下記）を使う、と割り切った。

### どう作ったか

| | |
|---|---|
| 複製の番号 | `edit.js` の `down()` が、掴んだ要素**自身**の `id` 末尾 `#N`
  （`LayoutDom.One` が繰り返しに付ける）を正規表現 `/#(\d+)$/` で読み、
  `DragStart(line, repeatIndex)` へ渡す。⚠️ 節点自身が `repeat=` を持つかは
  **C# 側**（`_dragOrigin.Option("repeat")`）で確かめる ── JS の値をそのまま信用しない |
  | 経路の分岐 | `Dragging(dx,dy)` で `col = repeatIndex % cols` を計算。`col>=1` なら
  横だけ `gap`・縦は既存の `TargetsY`/`SnapAxis`（Y軸だけ）で「上」。`col==0` または
  複製でなければ今までどおり `SnapMove`（両軸） |
| `gap` の書き方 | `Left`/`Top`/`Width`/`Height` と違い専用フィールドが無い（`Options` の中の1つ）。
  `WithGap(node, value)` が `Options` 辞書を複製して `["gap"]` を差し替えた新しい節点を作る
  ── **直すのは元の1行**（`LayoutNode.RenderLine`/`Write` がその1行だけ詰め直す。
  複製の描画は毎回 `LayoutDom.One` が同じ節点から計算し直すので、複製側には何も書かない）|
| 0未満にしない | `Math.Max(0f, ...)`（`Left`/`幅` と同じ考え方 ── エディタが壊れた値を作らない） |
| きざみ | ⭐ **効かせる**（`_step` で丸める）。理由: `Left`/`Top` と同じく「丸い数で書きたい」
  欲求は `gap` にもある。⚠️ **兄弟・親の辺への吸い付き（`TargetsX`/`SnapAxis`）は掛けない**
  ── `gap` は「間隔」であって「位置」でないので、比べる辺そのものが無い（比べたら
  「たまたま」の一致でしかない）。横の道しるべ線（`edguidex`）も出さない（同じ理由） |
| 数値欄 | ⭐ Inspector に `gap` の欄を足した。⚠️ **`repeat=` を持つ節点を選んだときだけ表示**
  （作者の pixelizer の教訓「空の欄を先に見せない」）。ドラッグでもタイプでも直せる |
| 取り消し | ⭐ 追加コードなしで効く ── 既存の `BeginAction`/`CommitAction`（木ごと文字列を
  積む・動かなければ積まない）にそのまま乗っているため |
