## 0. なぜやるか

作者の言葉:

> このゲームの画面をすべてドット絵にしようと思うと、それぞれのアセットを独立した
> ドット絵で作ってしまうと後から拡大縮小したときにドットサイズがバラバラになってしまうと思う。

### 🔴 もっと根が深いところ

⚠️ **アセットをどれだけ丁寧に揃えても、最後に画面全体が半端倍されるのでドットは絶対に揃わない。**
画面まるごと1枚の絵にしても同じ。**だから土台から直す。**

## 2. 揺らがない土台（🔴 破ったらドットが揃わなくなる）

1. **絵は拡大縮小しない。**1ドット = 1升（4px）で置く。
   ⚠️ 2倍にすると**その絵だけドットが2倍太くなる** ── いま起きている不揃いの再発。
   必要な大きさごとに**別々に描く**（これが 64×64 と 32×32 を分けた理由）。
2. **座標は4の倍数**（左・上・幅・高すべて）。
3. **字は段（8 / 12 / 16 / 24 ドット = 32 / 48 / 64 / 96 px）以外を使わない。**
4. **画面全体の倍率は整数**（下記 §3）。
5. `image-rendering: pixelated` を**全部の絵**に掛ける（いまは `crisp=yes` の1箇所だけ）。

### 例外にしてよい候補（未決）
- **演出（`fanfare` の誕生・獲得）だけ 2倍を許す。**比べる相手が画面にいないので破綻しにくく、
  「寄って見せている」と読める。⚠️ 許さないなら 64×64 を 256px で出す（今は380〜480px）。

## 3. 画面全体の拡大（整数倍と黒帯）

### 仕組み
- 絵の升目: **270×480 ドット**
- 端末の実ピクセルから **1ドットあたりの実ピクセル数 `P`（整数）** を決める:
  `P = floor(min(実幅 / 270, 実高 / 480))`（最低 1）
- 盤の実寸 = `270P × 480P`。CSS 上の倍率 `k = P / (4 × DPR)`
- 余った周りは**黒帯**

### 実機での見え方（試算・DPR込み）

| 端末（CSS） | DPR | P | 盤（CSS） | 今（半端倍）の余白 | 整数倍の余白 | 差 |
|---|---:|---:|---|---|---|---|
| 320×568 | 2 | 2 | 270×480 | 縦 178 | 横 50 / 縦 88 | ほぼ同じ |
| **360×640** | 3 | 4 | **360×640** | 0 | **0（ぴったり）** | ✅ |
| 390×844 | 3 | 4 | 360×640 | 縦 151 | 横 30 / 縦 204 | 縦 +53 |
| 430×932 | 3 | 4 | 360×640 | 縦 168 | 横 70 / 縦 292 | 横 −70 / 縦 +124 |

⭐ **今でも縦に 151〜178px 余っている**ので、増える分は思ったより小さい。
⚠️ ただし**大きな端末では横が 430→360 と 16% 狭くなる**。ここは見本で実機確認する。

### 大きさの段（これ以外を使わない）

🔴 **1ドット=4px に合わせるには、フォントも「1文字ドット=4px」で出す必要がある。**
PixelMplus10 は10ドット角なので **40px が唯一「絵と同じドットの太さ」になる大きさ**。

| 段 | 画面上 | フォントの1ドット | 用途 |
|---|---:|---|---|
| **本文** | **40px** | **4px（絵と同じ）** ✅ | ほぼ全部の字。名前・説明・釦・数字 |
| 強調 | 40px **Bold** | 4px（絵と同じ）✅ | ⭐ 大きさを変えずに強調できる ── **これを第一の手段にする** |
| 大 | 80px（2倍） | 8px（絵の2倍） ⚠️ | 大きい数字・演出。「寄って見せている」と読める場面だけ |
| 特大 | 120px（3倍） | 12px（絵の3倍）⚠️ | 演出のみ |

⚠️ **80px・120px はドットが太くなる**（＝§2の土台の例外）。**画面の題は字でなく絵にする**のが本筋。
⭐ 今の中央値26px → 40px なので**1.54倍**。当初見込み（48px＝約2倍）より軽い。

### 今との差
- いまの `size=` は **26種類**（13〜110px・11%が奇数）→ **40 / 80 / 120 の3つに丸め直す**
- 本文は 26px → **40px（1.54倍）**
- 🔴 **`panelmini`（素質表 6行×2列・今13〜19px）はこの密度では成立しない。**表の作り直しが要る
- ⭐ 決定4の後半「**できるだけ文章で説明しない**」がこの問題への答え。
  字を小さくするのでなく**言葉を減らし、絵と数字に置き換える**

⚠️ 字幅の実測（`scripts/measure.mjs`）は**フォント差し替え後に必ずやり直す**（§8-2）。

⚠️ 今は web も Unity も TTF（Mochiy Pop One）。しかも `scripts/measure.mjs` で
**字幅を実測して決めた寸法が数か所ある**（`skillinfo.txt` の高さ112など）── フォントを替えたら**再実測**が要る。

## 7. 機能の付け替え

### 調べた結果

| 対象 | 一覧を自動で作れるか | 根拠 |
|---|---|---|
| **`tap=`（45個）** | ✅ **できる** | `Shell.cs:224-314` の **switch 1本**に全部。骨組み側44個と過不足なく1対1。例外は `out`/`in` の2つ（`AppPage.razor:152`）だけ |
| **`hold=`（6個）** | ✅ できる | `Shell.cs:320-361` の switch 1本 |
| **`when=`** | 🟡 半自動 | 17箇所に散るが全部リテラル。例外は `detail-`/`pfill-`/`qfill-` → `Face.Shows` の1ホップ |
| **`bind=`** | 🔴 全体一覧は作れない | 前方一致・`s0name` の構文解析・key無視 の3種が実装に埋まっている |

⭐ ただし **`bind=` も「その画面で使える候補」なら骨組み自身が完全な一覧を持つ**（その `.txt` に書かれている名前がそれ）。

### 🔴 罠: 「冠」
`use=` で部品を差すと、`tap`/`bind`/`when`/`repeat` の値の頭に**差した枠の名前が付く**
（`Layout.cs:1426-1450` の `Layouts.Rename`）。

```
sortbar.txt:18   plate card ... tap=toggle
box.txt:19       bar   box  ... use=sortbar     → 実際に飛ぶ名前は "bar-toggle"
```

⚠️ 部品ファイル（9枚）を編集するときは冠を逆算しないと**嘘の候補**を出す。
差し込み元は `use=` を grep すれば全部出る（実測21箇所）ので**逆算は機械的に可能**。

### 決定6の範囲
- ⭐ エディタが開けるのは **`tap=`（と `hold=`）を一覧から選ぶ**まで
- `when=`／`bind=`／新しい機能は **Claude が引き受ける**（作者は絵と配置に集中する）

## 11. エディタの設計（⭐ 作者の指示「使用感が最も大事」）

### 11-0. 何のための道具か

この作り替えのあと、エディタでやることは**3つだけ**になる:

1. **背景の絵の上に、動く物（字・数・キャラ・アイコン）の場所を決める**
2. **絵に描いてある釦の上に、透明な押しどころを置く**
3. **その押しどころに機能（`tap=`）を付ける**

⚠️ 今のエディタは「枠や札を描く道具」だった。これからは **「絵に合わせて印を置く道具」**になる。

### 11-1. 調べたこと（既にある物）

LDtk（Haxe・オープンソース）と Tiled（C++/Qt・オープンソース）と Aseprite のソースを読んだ。
**借りるのは次の4つ**（`使用感` に直結する順）:

| # | 借りる実装 | 出典 |
|---|---|---|
| **①** | **見えないものは「白の実線＋黒の破線」の二重縁で描く** ── どんな絵の上でも輪郭が消えない。名札は「なし／選んだものだけ／全部」の3段階 | Tiled `src/tiled/mapobjectitem.cpp`、`src/tiled/preferences.h` の `ObjectLabelVisibility` |
| **②** | **「層を選ぶ」＝道具・カタログ・見え方が全部決まる** ── モード切替の UI を増やさない最短経路 | LDtk `src/electron.renderer/page/Editor.hx` の `get_curTool()`、`ui/palette/EntityPalette.hx` |
| **③** | **「薄くする」と「触れなくする」は別々の軸** ── 片方だけだと必ず不満が出る | Tiled `mapitem.cpp`（減光0.4＋暗幕0.6）と `abstractobjecttool.cpp`（`isUnlocked()` でヒットテストから外す）／LDtk `LayerDef.hx` の `inactiveOpacity` と `canSelectWhenInactive` |
| **④** | **升目を変えるときは全データを自動変換し、直前に復元点を取る** | LDtk `ui/modal/panel/EditLayerDefs.hx` の `new LastChance(...)` → `remapToGridSize()` |

参考（採らないが記録）:
- ズームを**有理数 `num/den` で持ち整数演算で往復**する（Aseprite `src/render/zoom.h`）── ドット絵で誤差が出ない。⭐ **これは採る**（下記 11-5）
- Tiled は**入力時スナップだけで既存のズレを矯正しない**。⭐ 我々は §8-1 の214行があるので**一括変換が要る**（④）
- LDtk のパネルは **固定300px＋TABで80px・盤は常に全画面でパネルは重ねる**（可変スプリッタを作らない）。1920px幅で **パネル16% / 盤84%**

### 11-2. 🔴 層（レイヤ）── この道具の背骨

⭐ **骨組みは1本の木のままで、層は「節点の性質」から**見なす**（ファイル形式も Core も変えない）。**

| 層 | 中身 | 見分け方 |
|---|---|---|
| **① 絵** | 背景・部品の絵 | 種類が `paint` |
| **② 動く物** | 字・数・キャラ・アイコン・帯・繰り返し | `bind=`/`repeat=` を持つ、または種類が `pixel`/`icon`/`bar` |
| **③ 押しどころ** | 透明な当たり判定 | `tap=`/`hold=` を持つ |
| **④ 入れ物** | 位置合わせ用の枠（`box`/`card`/`scroll`） | 上のどれでもない |

**層を1つ選ぶと**（②の借用）:
- 他の層は **薄くなる**（0.4）
- 他の層は **掴めない**（③の借用・別の軸）
- **道具箱の中身がその層のものに変わる**（例: 押しどころの層なら「囲んで作る」だけ）
- Inspector に出る欄もその層のものだけ

⚠️ **層は保存されない**（骨組みの字には出ない）。あくまで**編集中の見なし**。

### 11-3. 見えないものの見せ方（①の借用）

- 押しどころ・入れ物は **白の実線1px＋その上に黒の破線** で囲う ── 絵が明るくても暗くても輪郭が消えない
- 名札（部品の名前）は **なし / 選んだものだけ / 全部** の3段階を切り替えられる
- 選んでいないものは輪郭だけ（塗らない）。⭐ 重なっても下が見える（LDtk の `hollow`）

### 11-4. 升目と、既存のズレ（④の借用）

- **既定のきざみを 10 → 4 に変える**（今の既定10は升目と噛み合わない）
- 格子は**既定 ON**（4px。今は既定 OFF）
- スナップは**入力時だけ**・**四捨五入**（Tiled `snapToGrid()` と同じ形）
- 🔴 **一括「升目に合わせる」道具**を足す（§8-1 の214行の移行用）
  - 押す前に **復元点を取る**（LDtk の `LastChance`）── 取り消し1回では戻せない規模の変換なので
  - 変換の中身: 左/上/幅/高を4の倍数へ四捨五入。⚠️ **幅・高は 0 にしない**（最低4）
  - 変換後に**何行が動いたか**を出す（LDtk は変更範囲を光らせる。ここは件数で足りる）

### 11-5. 拡大（Aseprite の借用）

- ⭐ **倍率は「1ドットが画面上で何px か」で持つ**（整数のみ: 1, 2, 3, 4, 6, 8）
  - 1080設計px = 270ドット。1ドット=4px なら盤は1080px幅で表示される
- 内部は **有理数（num/den）** で保持し、画面↔設計の往復を整数演算で閉じる（誤差が出ない）
- ⚠️ 今の「器に合わせる半端倍率」は**編集中も使わない**（ドットが不揃いに見えて判断を誤る）

### 11-6. 押しどころの作り方（新しい一手）

⭐ **道具箱から掴んで落とす**（今の形）は「絵の上に印を置く」には向かない。
**押しどころの層では「絵の上をドラッグして囲むと、そこに押しどころができる」**にする
（Tiled の矩形オブジェクト作成 `createobjecttool.cpp` と同じ形）。

- ドラッグ中は**半透明のプレビュー**を出し、**離して初めて1つの取り消し**になる（Tiled と同じ順序）
- 作った直後に **`tap=` を選ぶ一覧**が開く（絵に機能を付ける、が1続きの動作になる）

### 11-7. 仮置きの絵（決定9）

- まだ無い絵は**コードで生成**する。**仮と分かる見た目**にする:
  - 斜線 ＋ 枠 ＋ 名前（小さく）／本番の絵と絶対に見間違えない
- 置き場所に**同じ名前の本物**が現れたら、自動でそちらを使う（仮は消さなくてよい）
- ⭐ 32×32 の上半身は、64×64 の頭のあたりを切り出して仮置きにする（§5）

### 11-8. 機能（`tap=`）の付け方（決定6）

- 一覧は **`Shell.cs:224-314` の switch から機械的に作る**（45個・§7で検証済み）
- 🔴 **部品ファイルを編集しているときは「冠」を逆算して出す**
  （`cell.txt` の `tap=one` は、差し込み先によって `cellA-one`/`cellB-one`/`cell-one` になる）
  - 画面に「この部品は `cellA-` `cellB-` `cell-` として差されています」と出す
- `when=`／`bind=`／新しい機能は**エディタから触らせない**（Claude が引き受ける・決定6）

### 11-9. 画面の作り

⭐ 今のエディタで作者が選んだ形（盤を主役・脇は細く・道具箱は上の帯）を**そのまま活かす**。
足すのは**層の切替**だけ。

```
┌───────────────────────────────────────┐
│ 上の帯: 画面▼ / 保存 / 取消 / 拡大 / 格子      │
│ 道具箱: 層の切替 [絵][動く物][押しどころ][入れ物] │
├──┬────────────────────────────┬──┤
│木 │            盤（主役）              │欄 │
│細 │   背景の絵＋動く物＋押しどころの輪郭      │細 │
└──┴────────────────────────────┴──┘
```

- パネルは**固定幅**（可変スプリッタは作らない ── LDtk と同じ割り切り）
- ◀▶ で畳める（実装済み）
- ⚠️ **盤は縦長なので、脇を畳んでも大きくならない**（§3）。近寄るのは拡大（11-5）で

### 11-10. 実寸で確かめる

- **整数倍＋黒帯**で、実機の見え方をそのまま出す窓を作る（§3の試算を実物で確認するため）
- 端末の幅を選べるようにする（320 / 360 / 390 / 430）── 罠23「1つの寸法で合わせた値はその寸法でしか合わない」

### 11-12. うまくいかないときの見せ方（⭐ `/ux-design` の観点で点検して足した）

道具の使用感は「うまくいっているとき」より**「うまくいかないとき」で決まる**。
下の5つは、黙って何も起きないことが**絶対に**ないようにする。

| 場面 | 見せ方 |
|---|---|
| **絵がまだ無い** | 斜線＋名前の仮置きを出す（§11-7）。⚠️ 空白にも「？」にもしない ── 「まだ描いていない」と「名前を間違えた」は別物なので、**別の見た目**にする |
| **升目に合っていない行がある** | 開いた直後に「**この画面に升目から外れた部品が N 個あります**」と1行で出し、押すと一括変換（§11-4）へ。⚠️ 勝手に直さない |
| **保存できない** | 既にある2つの守り（往復が閉じない／開いた後に外部で変わった）をそのまま使う。⚠️ **黙って書かない・黙って諦めない** |
| **まだ何も置いていない画面** | 空の3列を見せない（実装済みの段階制）。何をすればいいか1行だけ出す |
| **重い処理**（32枚の一括変換・仮置きの生成） | 件数と進み具合を出す。⚠️ 固まったように見せない |

⭐ この5つは**新しい仕組みを増やさない** ── 既にある「不備の一覧」「保存の守り」「段階制」に乗せるだけ。

### 11-11. やらないこと（決めておく）

| やらない | 理由 |
|---|---|
| 絵の中の形に吸い付く（輪郭検出） | 升目スナップ＋拡大で足りるはず。使ってみて不満が出たら考える |
| 可変幅のスプリッタ | LDtk も作っていない。固定幅＋畳むで足りる |
| コマンド方式の取り消し | 今の snapshot 方式で足りている（LDtk も snapshot）。⭐ ただし危険操作の前の**復元点**は足す（11-4） |
| 層を骨組みの字に書く | 見なしで足りる。ファイル形式を増やさない |
