# 画面の作法

⚠️ **これは実装側の決めごとです。**遊んで発見しえないので攻略ページには書きません。
（旧 Wiki §1 から移設）

### 見た目の正解

> **UI はポップカジュアル、キャラはドット絵。**

⭐ **2層に分けて別々に決める。**混ぜない。

| 層 | 正解 | 出所 |
|---|---|---|
| **UI（画面まわり）** | 太い輪郭 + ぼかし無しの影 + 白と濃紺 | `参考/画面モック.html` |
| **キャラ（モンスター）** | 16×16 のドット絵 | まものダンジョン＋ |

**UI の作法は3つだけ**（`src/style.css` が唯一の出所）:

1. **暗色は `#2B3350` 1色。**輪郭も文字も影も全部これ。他の暗い色を足さない
2. **輪郭（2.5〜4px）+ ぼかし無しの影（`0 4px 0`）。**ぼかした影は使わない
3. **彩度の高い色はキャラだけ。**UI の面は白。塗るのは主導線1つ（オレンジ `#FF9F43`）だけ

**キャラはドット絵のまま。**⭐ **変異＝パレットスワップ**。1体ぶんのドットで変異個体が無限に作れる。
⚠️ モックのモンスターが丸に目と口なのは**モックの手抜き**であって、絵柄の宣言ではない。

### ⚠️ 絵を伸ばすときは縦横比を保つ

⭐ **ドット絵（キャラクター）は、縦横を別々に伸ばさない。**
必ず同じ倍率で拡大縮小する。

⚠️ **判定の幅に絵を合わせようとして潰さない。**
潜入の親を「塞いでいる幅」いっぱいに引き伸ばしていたとき、
親が横に潰れて**別の生き物に見えた**（56〜75 の幅に対し絵の高さは 30）。

⭐ **判定と見た目を合わせたいときは、絵ではなく「面」を判定の寸法にする。**

| | |
|---|---|
| 塞いでいる幅・当たり判定 | **面（帯・板）**で示す。⭐ ここは伸ばしてよい |
| キャラクター | ⭐ **縦横比を保ったまま**、その面の中に収まる大きさで置く |

**伸ばしてよいもの**: 9スライスの器（`panel` / `button` / `pill`）・帯・面・影の楕円。
**伸ばしてはいけないもの**: `PixelSprite` から作った絵すべて（種族・卵）。

⚠️ `Image` なら `preserveAspect = true`、`SpriteRenderer` なら
`localScale` の x と y に**同じ値**を渡す。

### スマホの作法（`src/style.css` の器が唯一の出所）

**縦持ち1本。**幅は `min(100%, 430px)`（⚠️ 実機は 320〜430 まである。px 固定にしない）。

| | |
|---|---|
| 器 | **3層**: 固定の上段 / **唯一スクロールする本体** / 固定の下段 |
| 高さ | `100svh`。⚠️ `100dvh` はバーの出入りで値が変わり、固定した下段が動く |
| ページ | `html,body { overflow: hidden; overscroll-behavior: none }` で**絶対にスクロールさせない** |
| 安全域 | `env(safe-area-inset-*)`。⚠️ `viewport-fit=cover` が無いと常に 0 |
| スクロール層 | `overscroll-behavior: contain`（端でページ側へ伝わるのを止める）+ `overflow-x: hidden` |
| タップ域 | **最低 44px 角**。見た目が小さいものは透明な余白で広げる |
| 反応 | `touch-action: manipulation`（ダブルタップ拡大の 300ms 待ちを消す）|
| 手触り | `-webkit-tap-highlight-color: transparent` / `user-select: none` |
| 横持ち | 「粗いポインタ × 低い横長」のときだけ回転を促す（デスクトップには出さない） |

**画面ごとの層分け**（⚠️ 二重スクロールを作らない。1画面に1つ）:

| 画面 | 固定 | スクロール |
|---|---|---|
| ホーム | 全部（収まりきるのが仕様） | なし |
| 巣 | 遊び方の一行 | 巣の一覧 |
| 発射 | 全部 | なし（フィールドを実測で内接させる） |
| 戦闘 | 下のスキルシート | 場（arena） |
| 孵化 | なし | 卵の一覧 |
| 配合 | 上の2枠 + 結果 | 相手の一覧 |
| BOX | 上の詳細 + 並べ替え | グリッド |

⭐ **大きさを決め打ちしない。**発射のフィールドとホームのドット倍率は
`ResizeObserver` で**実際の空き寸法を測って**決める（ドット絵は整数倍だけ選ぶ）。
⚠️ **端末の枠（角丸 + 太枠 + 影）は描かない。**モックのあれは
「7画面を並べて見せるための台紙」であって、設計ではない。

**画面の構成もモックに従う**（色や書体だけの話ではない）:

```
ホーム（ハブ）
  ├ 上段  タイトル / BOX の空き
  ├ GOAL  倒すべき壁の名前
  ├ 舞台  編成3体を三角に配置（リーダーを手前に大きく）+ 台座
  ├ 数値  編成 / スピード合計 / 飛距離
  └ 下段  4パネル（BOX・孵化・配合・探索）── 探索だけ塗る

各画面  上段に ‹ / 見出し / 状態ピル。‹ でホームへ戻る
  巣      巣カード（巣の絵 + 属性バッジ + 名前 + 挑戦）
  発射    フィールドを枠に内接させる
  戦闘    左に味方3体（小さくリスト）/ 右に敵（絵を大きく）/ 下に白いシート
  孵化    卵スロット（殻だけ見せる。中身は孵るまで出さない）
  配合    上に2枠 + RESULT EGG / 下に相手を選ぶリスト
  BOX     上に選んだ1体の詳細 / 下にアイコンのグリッド
```

⭐ **枠1（CTなし）は「その種族の通常攻撃」。**戦闘のシートで幅いっぱいの1行にして、
2・3と質を変える（モックが スキル1 をそう置いていた）。

⚠️ **「必殺の位置」と書いてあったのは誤り**（2026-08-17 訂正）。
枠1 に CT が無いのは**行動できない手番を作らないため**であって、大技だからではない。
⭐ コード側は最初から正しかった（`Skills.cs`「全スキルが CT 中でも必ず打てる札が残る」）。
⚠️ ここを「必殺」と読むと、枠1 に強い技を置く方向へ設計が流れる。**通常攻撃として据える。**

⚠️ **共通ルールの「AIっぽさの回避」（角丸で囲わない / 影を全要素に付けない /
グラデーションを使わない）は、このプロジェクトでは意図的に外している。**
無難に寄せた結果の角丸カードではなく、**1つの明確な選択**をしている。
規則の趣旨（あえて選ぶ）はこちらで満たす。ここを「規則に反している」だけの理由で戻さない。

⚠️ **モックにあって企画に無いものは採らない**（AP / Lv / SP / 実時間の孵化 / 通貨 / WAVE /
パッシブ / 弾数）。⭐ **モックは「見た目と構成」の資料であって「仕様」ではない。**
空いた枠には**実在する事実**を入れる（例: モックの「NOW EVENT」の位置 → 倒すべき壁の名前）。

## 個体の札は1つの部品（2026-08-18）

⭐ **BOX の詳細と配合の親札は同じ部品**（`CreaturePanel`）。並びも同じ:

```
┌────────────┬──────────────────┐
│(属)        │ Lv 55/55         │
│            │ タマル           │
│    絵      │ c001 1代 変異0   │
│            ├──────┬────┬────┤
│            │      │素質│強化│
│            │ HP   │  9 │ +6 │
└────────────┴──────┴────┴────┘
┌──────────────────────────────┐
│[特性]                        │
└──────────────────────────────┘
        ┌────────┐
        │  技1   │
        └────────┘
┌────────┐      ┌────────┐
│  技2   │      │  技3   │
└────────┘      └────────┘
```

⚠️ **ラフ図は配置の資料であって、意匠の指定ではない。**
線を引くのは「**無いと読めない**」ところだけ。それ以外は共通ルール
（余白で離す → 面で分ける → 線は一辺だけ）をそのまま使う。

| どこ | 何で分けるか | なぜ |
|---|---|---|
| ステの表 | **横罫**（行ごと）＋ 見出しの下だけ一段濃い1本 | 6行を左から右へ目で追うので線が要る |
| 表の列 | **右揃えだけ**（縦罫を引かない）| 数が揃えば列は立つ。線を足しても読みやすくならない |
| 特性・技 | **面**（明度を一段落とす）| 塊が分かればよい。囲うと表と同じ重さになる |
| 絵・見出し | **余白と字の大きさだけ** | 絵は十分大きく、名前は十分太い。囲う理由が無い |

⚠️ **全部を枠で囲った版を1度作って外した。**絵も見出しも特性も技も同じ重さになり、
「どこを見ればいいのか分からない」札になった。

⚠️ **画面ごとに欄を組み直さない。**組み直した結果、
**特性の働きが BOX にしか出ていなかった**（配合では名前だけだった）。
同じ個体は、どの画面でも同じ顔で出る。

⭐ **違うのは寸法だけ**（`Wide` = BOX の 984 / `Narrow` = 配合の 460）。
⚠️ **狭いからといって積み替えない。**460 でも絵は左、表は右。
積み替えると、同じ個体が画面によって別の札に見える
（実際、一度 縦積みにして「ラフと配置が全然違う」と指摘された）。

⭐ **ステの表は「素質 / 強化」の2列**で、⭐ **足すと実値になる**。

- 素質 ＝ 種族基礎 ＋ 素質（得意・不得意の ±15% 込み）＝ 育てる前の実値
- 強化 ＝ 育てて**実値がいくつ増えたか**（振ったポイントではない）

⚠️ 生の素質（0〜40）だけを出すと、足しても戦闘の数にならず**札から強さが読めない**。
⚠️ 「39（9+6）」と1つの字に詰めるのも駄目 ── 2体を並べたときに桁が揃わず比べられない。

⭐ **見る場所と押す場所を分ける。**押しどころ（出撃・餌・合成・そだてる・技を鍛える・逃がす）は
札の**外**、下に1列。⚠️ 札の中に混ぜると、読んでいる途中で指が触る。

⚠️ **中の枠を器の枠へ食い込ませない。**器（Detail / 親カード）は9スライスの枠を持っていて、
枠の線が内側へ 20px ほど描かれる。⭐ 内側の箱は左右・下に **18px 以上**空ける
（空けないと「箱が枠に切られている」ように見える。実測で外した）。

## ⭐ 字で説明せず、置き方と動きで分からせる（2026-08-20・作者の指示）

⚠️ 説明の文を画面に置かない。⭐ 読ませるのは**絵と数**だけ。

| 書きたくなること | ⭐ 代わりに置くもの |
|---|---|
| 「のこり 6 回」 | **さいころの絵を6つ並べる。**使ったぶんは輪郭だけに変わる |
| 「壁 ＝ 攻撃」 | **上の帯と盤で同じ絵**（剣）を出す。同じ絵なら結び付けは説明が要らない |
| 「HPが270足りない」 | **錠前の絵**と、押せない札と、暗く落とした道 |
| 「敵×2」 | **髑髏の絵を2つ**置く |
| 「どちらの道を行く？」 | **2つ並べて置くこと**そのもの |
| 「これで最後」 | 最後のさいころを**脈打たせる**（`Throb`）|
| 「なにもない」 | **何も置かない**（無いことは、無いことで伝わる）|

⚠️ **数は字ではない。**`1,258` や `28%` は説明ではなく事実なので置いてよい。
消すのは**言い換え・言い聞かせ・手順の説明**のほう。

### ⚠️ 素材は必ずダウンロードした物を使う

⚠️ 色を塗った四角、`▲`／`▼` の記号、漢字1文字の代用 ── これらは全部
**手で描いた絵**であって、素材ではない。角が立ち、大きさが揃わず、様式が混ざる。

| 通し口 | いつ使うか |
|---|---|
| `Ui.Icon` | 絵の札（`Resources/UI/icon/*`・Kenney CC0）|
| `Ui.Plate` | 9スライスの面（`panel` / `pill`・Hyper Casual UI CC0）|

⚠️ 素の <see cref="UnityEngine.UI.Image"/> に色を塗るのは**線と帯だけ**。
⭐ 器と絵は必ず上の2つを通す。

### ⚠️ 絵の選び方で踏んだこと（2026-08-20）

- `dice`（傾いた2個のさいころ）を残り回数に使ったら、**散らばった破片**に見えた
  → ⭐ `dice_empty`（正面の1個）に。使ったぶんは `d6_outline`（輪郭だけ）
- `direction_n`（方位の矢印）には **`N` の字が入っていた** ── 字を消す方針に反する
  → ⭐ `arrow_right` を 90 度回して上下を作る（`Ui.Icon` の `turn`）

## ⭐ ★の枠と、常設のタブバー（2026-08-20・作者の指示）

ソシャゲの意匠に寄せるために足した2つ。

### ★の枠

⭐ 升の**縁の色で序列を出す**（下から 灰→緑→青→紫→金）。
⭐ 上位ほど**縁が太い**（★4以上は 10、それ未満は 6）── 色だけだと序列が読みにくい。

| どこに | 何の★か |
|---|---|
| 卵の升（`Ui.EggCell`）| `Egg.Rarity` |
| 個体の升（`CreatureCell`）| **素質の合計**から逆に引く（`Nests.RarityOfWildTotal`）|

⚠️ **升の「後ろ」には置けない。**升の面は親自身の `Image` なので、子はどう並べても
その上に描かれる。⭐ だから枠は「色の外側 ＋ 白の内側」の2枚組
（`Ui.Ring` と同じ手）。内側を省くと升が塗り潰されて絵が消える。

⚠️ ★5 の金は `Ui.Accent`（主導線の黄）と近い。
⭐ **別の水路**として扱う ── 差し色は押しどころ、★は升の縁。
押しどころに★の色を塗らない限り混ざらない。

### 常設のタブバー

⭐ ホーム / 探索 / 配合 / BOX の4枚。**いま居る所は上辺に差し色の帯**を1本。

⚠️ 札そのものを黄色にしない ── 黄は「1画面に1つの主導線」の色で、
タブに使うと画面の中の主役とぶつかる。⭐ 区切りと同じ約束で**一辺だけ**。

⚠️ **戦闘と潜入では出さない。**タブも「戻る道」なので、‹ を隠しておいて
タブから抜けられては意味がない（`canBack` と同じ条件で出す）。

⚠️ タブのある画面に **‹ を出さない**。タブが行き先を全部持っているので、
‹ は「ホームへ戻る」だけの重複した道になる。

⚠️ タブバーは本体の下 232px を**覆う**（Body は縮まない）。
⭐ 実測で食い込むのは**スクロールする層だけ**だったので、そこだけ窓を縮める
（`App.ReserveDock`）。⚠️ 固定配置の部品には触らない ── 動かすと配置の出所が2つになる。
