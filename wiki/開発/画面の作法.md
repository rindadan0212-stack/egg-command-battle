# 第1部 規則

## 1. 器 ── 画面の大きさと拡大

**縦持ち1本。**⭐ 設計座標は **1080×1920 固定**で、実機へは**外枠の拡大縮小だけ**で写す。

| | | 出所 |
|---|---|---|
| 升目 | **270×480 ドット**（1ドット＝設計 **4px**）| `Layouts.ScreenWidth/Height`（`Core/Layout.cs:537`）|
| 拡大 | ⭐ **整数倍を第一候補。届かないときだけ窓に合わせた倍率**（下記）| `wwwroot/index.html` の `fit()` |
| 余り | **左右は黒帯**（`html,body { background:#0d1220 }`）| `stage.css` |
| 上のバー | 🔴 **無い**（`TopBarHeight = 0`）| `Core/Layout.cs:550`・`frame.txt` に `top` 節点なし |
| 下の帯 | **232px**（`dock` が 1688 から）| `Layouts.DockHeight`（`Core/Layout.cs:553`）・`frame.txt` |
| はみ出し | `#stage-wrap { overflow: hidden }`。⚠️ **格子の中央寄せに頼らない** ── 中身が器より広いとき溢れ方が当てにならない | `stage.css` |

### ⭐ 拡大の決まり（2026-08-30 に変わった）

```
kFit  = min(窓幅/1080, 窓高/1920)      ← 窓にちょうど収まる倍率（縦べた付き）
kInt  = 整数倍（1ドットが実ピクセル整数）
使うのは kInt。ただし縦が埋まらないときだけ kFit
```

🔴 **縦は窓にべた付き、横は余ってよい**（作者の指示 2026-08-30）。
⚠️ **整数倍だけでは満たせない。**実測: 作者の窓は中身の高さが約 915px で、整数倍に必要な
936px に **21px 届かない**。届かせるには 90 設計px 切る必要があるが、切ってよいのは下の
36px だけ（上は EXP の字が y=0 から始まる）── だから縦半分（270×480）に落ちていた。

⭐ **整数倍で埋まるならそちらを採る**（ドットの太さが揃うほうが良い）。埋まらないときだけ
窓に合わせた倍率へ落とす。⚠️ 半端倍率では絵のドットの太さが 1px ぶん不揃いになる
（2px と 3px が混じる）が、`image-rendering: pixelated` が効いたままなので**ボケはしない** ──
にじまず、太さだけが揃わない。

⚠️ `devicePixelRatio` は `2.9999998` のような値を返す ── **そのまま `floor` すると1段落ちる**
（誤差を丸めてから使う）。

⚠️ **端末の枠（角丸 + 太枠 + 影）は描かない。**モックのあれは「7画面を並べて見せるための
台紙」であって、設計ではない。

## 2. 寸法の階段 ── 「大きく」「小さく」と言われたときに選ぶ段

🔴 **勝手に数字を決めない。**下の段から選ぶ。段に無い値を使いたいときは、理由を残すこと。

### キャラの絵の枠（`pixel`）

> **64 の倍数**。`SpeciesTable.ArtDots` が 64 で、16ドットの絵も 64ドットの絵も
> 「64升の絵」として同じ辺に伸びる（16 も 64 も 64 の約数なので**1ドットあたりの画素数は
> 必ず整数**）。

| 段 | いま使っている場所（実測 2026-08-30） |
|---:|---|
| **128** | 放置帯 `walker`（※現在192）・図鑑 `book`・試練 `trial`・編成 `party`・配合 `panelmini` |
| **192** | 戦闘 `unit`・放置帯 |
| **256** | 探索の巣 `encounter`・ヌシの札 |
| **384** | BOX 詳細 `panel` |
| **512** | 誕生演出 `fanfare` |

⚠️ **例外は2つだけ**（どちらも理由がある）:

| 枠 | どこ | なぜ |
|---:|---|---|
| **48** | 卵の升 `eggchip` | 64 に満たないので、その絵自身のドット数で整数倍を数え直す（16ドット→3px/ドット で 48 にぴたり） |
| **200** | BOX 一覧の升 `cell`（`cell.txt:23`） | ⭐ `crop=256` で**意図的に見切れさせる**枠。絵は 256 で描き、窓が 200 |

### 押しどころ（`button`）

> **高さ 112 以上**（`Layouts.TapHeight`・`Core/Layout.cs:541`）。🔴 **意匠で下げない** ──
> 指で押せる下限で、`TapTooShort` が見張っている。小さくできるのは**幅と字**。

実測（2026-08-30）: **112 が 42件**・130 が 1件・150 が 3件。⭐ 迷ったら 112。

### 座標のきざみ

> **4の倍数**（升目に載せる）。骨組みエディタのきざみも既定4。

⚠️ **これは努力目標であって、検査されていない。**実測（2026-08-30）: 全 418 節点のうち
**220 節点（53%）が4の倍数でない**（`panel` 27・`tree` 26・`panelmini` 26 …）。
⭐ 検査があるのは `sim import-screen` が**出した**骨組みだけ
（`ImportScreenTests.座標はドット4倍で必ず4の倍数になる`）。
🔴 **新しく置くものは4の倍数にする。既にずれているものを一斉に直さない**（見た目が動く）。

### 余白（`gap`）

実測（2026-08-30）: **12 が既定**（19件）。ほかに 4 / 6 / 10 / 16 / 88 / 276。
⭐ 並べるものの隙間は **12** から始める。

### ⚠️ 横に並べるときの幅の式

⚠️ `(内寸 − 24) / 個数` と書いてはいけない。**隙間の数は「個数−1」**なので、
3個（隙間2つ）でだけ正しく、4個にすると **12px はみ出す**。

```
1つぶんの幅 ＝ (内寸 − 隙間 × (個数 − 1)) ÷ 個数
```

⭐ 実測で確認（編成画面・4枠）: x = 24 / 261 / 498 / 735、幅 225、右端 **960** ＝ 内寸ちょうど。

### ⚠️ 本数は決め打ちしない

⭐ **数えるものが増えうるなら、必ず `Count` から引く。**
⚠️ 幅の式も同じ ── `(w - 20) / 2` は2本でだけ正しい。
（→ [§4 分かれ道が2本で止まっていた](#4-分かれ道が2本で止まっていた2026-08-20)）

## 3. 色と意匠

> **UI はポップカジュアル、キャラはドット絵。**

⭐ **2層に分けて別々に決める。**混ぜない。

| 層 | 正解 | 出所 |
|---|---|---|
| **UI（画面まわり）** | 太い輪郭 + ぼかし無しの影 + 白と濃紺 | `参考/画面モック.html` |
| **キャラ（モンスター）** | ドット絵。**作者の手描きは 64×64**／仮置きは 16×16 | まものダンジョン＋ |

**UI の作法は3つだけ**（`game/EggCommand.Web/wwwroot/stage.css` が唯一の出所）:
⚠️ 色は定数（実測 2026-08-30 時点で **15個**）。**ここで新しい色を作らない。**

1. **暗色は `#2B3350` 1色。**輪郭も文字も影も全部これ。他の暗い色を足さない
2. **輪郭（2.5〜4px）+ ぼかし無しの影（`0 4px 0`）。**ぼかした影は使わない
3. **彩度の高い色はキャラだけ。**UI の面は白。塗るのは主導線1つ（`--accent: #f59e0b`）だけ

**キャラはドット絵のまま。**⭐ **変異＝パレットスワップ**。1体ぶんのドットで変異個体が無限に作れる。
⚠️ モックのモンスターが丸に目と口なのは**モックの手抜き**であって、絵柄の宣言ではない。

### 🔴 色は「掛けた側」ではなく「持っている側」の得失

⚠️ 挑発を**良い側（緑）**で出していた（2026-08-23 修正）。挑発は相手に付ける弱化なので、
緑だと「相手が強くなった」と読めてしまう ── **狙い先を選ぶ、まさにその瞬間**に逆の意味を出す。

⭐ 根っこは「`ActiveStatusBadges` に検査が1件も無かった」こと。
⭐ いまは 15 件（強化7・弱化8）が好悪を全種類ぶん押さえている（`StatusBadgeTests`）。

### ⭐ 得意・不得意は緑と赤（2026-08-30・作者の指示）

⭐ ステの**印（▲▼）と名前と数**を、同じ規則で色分けする（`Face.Tint` の `"key"`）。
⚠️ 数だけ色分けして名前を白のままにしない ── 実測で「どのステが得意か」が読み取れなかった。

### ⚠️ 「AIっぽさの回避」は意図的に外している

⚠️ 共通ルールの「AIっぽさの回避」（角丸で囲わない / 影を全要素に付けない /
グラデーションを使わない）は、このプロジェクトでは**意図的に外している**。
無難に寄せた結果の角丸カードではなく、**1つの明確な選択**をしている。
規則の趣旨（あえて選ぶ）はこちらで満たす。ここを「規則に反している」だけの理由で戻さない。

## 4. 絵の置き方

🔴 **描き方（実ドット数・目録の作り直し）は [絵の描き方](絵の描き方.md) が唯一の出所。**
ここには「置くときの規則」だけを書く。

### ルールは2つ ── 絵の種類で分かれる

> 🔴 **`paint`・`icon` は「実ドット数 × 4」で置く。引き伸ばさない。**
> 🔴 **`pixel`（種族・卵の絵）は「枠に収まる最大の整数倍」で置く。**

⚠️ **2026-08-29 に分かれた。**それまでは「絵はすべて拡大縮小しない」だったが、`pixel` は
**同じ絵が 48〜512px の枠へ次々に出る**ので、実寸に固執すると小さい枠では切れ、大きい枠では
余った（→ [§7 絵と枠が噛み合っていなかった](#7-絵と枠が噛み合っていなかった2026-08-29)）。

| | |
|---|---|
| `paint` / `icon` | 枠 ＝ **実ドット数 × 4**。合わなければ `LayoutDom.FitDotsStyle` が位置だけ中央寄せして**実寸のまま**置く（＝見た目が壊れる）。`PicFrameSizeTests` が落とす |
| `pixel` | `LayoutDom.FitArtStyle`（`LayoutDom.cs:567`）が枠に合わせて**整数倍で**伸ばす。半端倍率は使わない |

### 引き伸ばしてよい場面 / いけない場面（作者の3規則・2026-08-29）

| | |
|---|---|
| **比較対象が画面に無い**（誕生演出 `fanfare`） | 大きくしてよい。⭐ 512（64×8） |
| **見比べる場面**（放置帯・戦闘・図鑑・配合・試練・探索一覧） | 🔴 **枠を固定して共通化する。**大きさが違うと「この種族は大きい」という嘘の印象になる |
| **BOX一覧の升**（`cell`） | ⭐ **意図的に見切れさせる**（`crop=256`）。どこを見せるかは種族ごとに違う ── `SpeciesArt.FocusOf` が持ち、書いていない種族は絵の囲みから割り出す |

### ⚠️ 縦横を別々に伸ばさない

⭐ **ドット絵は必ず同じ倍率で拡大縮小する。**
⚠️ **判定の幅に絵を合わせようとして潰さない。**潜入の親を「塞いでいる幅」いっぱいに
引き伸ばしていたとき、親が横に潰れて**別の生き物に見えた**（56〜75 の幅に対し絵の高さは 30）。

⭐ **判定と見た目を合わせたいときは、絵ではなく「面」を判定の寸法にする。**

| | |
|---|---|
| 塞いでいる幅・当たり判定 | **面（帯・板）**で示す。⭐ ここは伸ばしてよい |
| キャラクター | ⭐ **縦横比を保ったまま**、その面の中に収まる大きさで置く |

**伸ばしてよいもの**: 9スライスの器（`panel` / `button` / `pill`）・帯・面・影の楕円。

### ⭐ 敵は左右反転で描く（作者の指示）

⚠️ 絵は全部おなじ向き（右向き）で描いてあるので、そのまま並べると**敵も味方も同じほうを向く**
── どちらがどちらか、絵だけでは読めない。⭐ 敵だけ反転すれば向かい合う。

| どこ | 何を反転するか |
|---|---|
| 戦闘 | 敵側の体だけ |
| 探索の札 | ⚠️ 札に出るのは**その巣の親** ＝ 常に敵 |
| ホームのヌシ | 常に敵 |
| 放置の帯 | 相手だけ。⚠️ 味方も**言い切る**（器を使い回すので前の向きが残る） |
| 潜入の盤 | 親と道中の雑魚。⚠️ 発射台・投げる個体・卵は反転しない |

| ⚠️ やらないこと | なぜ |
|---|---|
| 札や器ごと反転する | 中の字まで裏返る（HP の数字が鏡文字になる）|
| `x *= -1` と掛け算で書く | 描き直すたびに向きが入れ替わる |
| 「敵かどうか」に既定値を置く | 次に絵を足した人が決めないまま通せる |

（→ [§5 pivot が端だと反転で絵が枠の外へ飛ぶ](#5-pivot-が端だと反転で絵が枠の外へ飛ぶ2026-08-21)）

### ⭐ 絵の下に影を敷く（2026-08-30・作者の指示）

⭐ **キャラの絵が出る画面ではすべて同じ影**。絵の裾に少し食い込ませる。
🔴 色は `Face.ShadowCss` の**1か所だけ**、形と位置は骨組みが持つ。

⚠️ `round` では作れない ── 「正方形で描かれる」検査（`NotSquare`）があるので横長にできない。
⭐ `bar`（`border-radius:9999px` の丸薬型）を割合1で使う。

**他の画面へ当てるとき**: 骨組みに `shade bar <左> <上> <幅> <高> bind=shade` を**絵より前**に
置き、その画面の `DomFill` に `Tint: key=="shade" ? Face.ShadowCss : …` と
`Ratio: key=="shade" ? 1 : …` を足す。

### ⚠️ 素材は必ずダウンロードした物を使う

⚠️ 色を塗った四角、`▲`／`▼` の記号、漢字1文字の代用 ── これらは全部
**手で描いた絵**であって、素材ではない。角が立ち、大きさが揃わず、様式が混ざる。

⚠️ **絵は「並びの中で読める」ものと「単独で読める」ものが違う。**流用するときに確かめること
（→ [§6 無地の絵は単独で置くと意味を失う](#6-無地の絵は単独で置くと意味を失う2026-08-21)）。

### ⭐ 絵の通り道は `Core.Art` が唯一の出所

⚠️ 絵の名前を画面側に散らかさない。⭐ Core に表を1つ置き、両方のエンジンがそこを読む。

| | |
|---|---|
| `Art.StatusIcon(kind)` | 状態異常 → `icon/status-*` |
| `Art.All()` | ⭐ **表が指す絵、全部**。存在の検査と死蔵の検査はここだけを舐める |
| `Art.Placeholder` | ⭐ **まだ仮の絵**。差し替えたらここから外す |

⭐ **今後キャラクター・ボタン・背景を足すときも同じ形**：①辞書を1つ増やす ②引く関数を1つ足す
③`All()` に `foreach` を1つ足す。⚠️ これで検査（実体があるか・誰にも指されていないか）が
**自動で新顔も見る**。

⚠️ **描き方（PNG か CSS か）は `Art` では決めない。**

### ⭐ 種族の絵は「あらかじめ差し替えた PNG」で通す

⚠️ **`Core.Art` とは別の通り道。**骨組みは種族もパレット添字も知らない（`PixelSprite`/`Palette`
の**実体**しか渡ってこない）ので、名前の表では引けない ── だから `SpriteManifest` が
**オブジェクトの参照**で引く。

| 段 | 唯一の出所 |
|---|---|
| 焼く | `SpritePng.RunDisplay`（`sim sprites`）→ `art/sprites/display/<種族id>-<パレット番号>.png` |
| 配る | `EggCommand.Web.csproj` の `CopyArt` + `SpriteManifestFiles` |
| 引く | `SpriteManifest.StemOf(sprite, palette)` |
| 出す | `LayoutDom.Dots` が `stem` があれば `<img>`、無ければ（卵など）SVG |

⚠️ **なぜ実行時に色を合成しないか**: 組み合わせは (種族×パレット) で**高々38通り**の有限集合。
⭐ 有限で小さいなら**先に全部焼いておくほうが速い**（1画素＝1 `<rect>` だった頃、
BOX 1画面で矩形32,535個）。

🔴 **焼き忘れると「古い絵が出る」を黙って許さない**:
- **テスト側**: `SpritePngTests.表示用PNGが最新である` が全38通りを焼き直してバイト比較
- **画面側**: `SpriteManifest.Exists` が実在しない絵を `icon-missing` で出す（🔴 黙って空の四角にしない）

### 🔴 流れる背景は道具に組ませる

背景の帯だけは**手で置かない**。⭐ `assets/ui/home-src/` の絵を `node tools/bg-band.mjs` に
かけると、繋がるように並べ直した PNG と、`home.txt` に写す行と `stage.css` の動きが出る。

> 🔴 **帯は「元・鏡・元・鏡」の4枚。2枚ぶん流して先頭へ戻す。**

⚠️ 2枚（元・鏡）で1枚ぶん流すのでは駄目 ── 流し終わりに映っているのは「鏡」なので、
先頭へ戻る瞬間に**画面全体が左右反転してパッと切り替わる**（実測: 山の帯で 1080×252 の
全画素が入れ替わっていた）。⭐ 手前の層ほど速く（空12 → 山24 → 遠くの地面48 px/秒）。

⚠️ `StageCssTests.流れる背景は輪が閉じている` が突き合わせて落とす ── **静止画では絶対に
捕まらない不具合**なので、この検査を消さないこと。

## 5. 部品と配置

### ⭐ 個体の札は1つの部品

⭐ **BOX の詳細と配合の親札は同じ部品**。並びも同じ:

```
┌────────────┬──────────────────┐
│(属)        │ Lv 55/55         │
│            │ タマル           │
│    絵      ├──────┬────┬────┤
│            │      │素質│強化│
│            │ HP   │  9 │ +6 │
└────────────┴──────┴────┴────┘
```

ところだけ。

| どこ | 何で分けるか | なぜ |
|---|---|---|
| ステの表 | **横罫**（行ごと）＋ 見出しの下だけ一段濃い1本 | 6行を左から右へ目で追うので線が要る |

⚠️ **画面ごとに欄を組み直さない。**同じ個体は、どの画面でも同じ顔で出る。
⭐ **違うのは寸法だけ**（BOX の 984 / 配合の 460）。⚠️ **狭いからといって積み替えない。**

⭐ **ステの表は「素質 / 強化」の2列**で、⭐ **足すと実値になる**。

- 強化 ＝ 育てて**実値がいくつ増えたか**（振ったポイントではない）

⚠️ 札の中に混ぜると、読んでいる途中で指が触る。

⚠️ **中の枠を器の枠へ食い込ませない。**器は9スライスの枠を持っていて、枠の線が内側へ
20px ほど描かれる。⭐ 内側の箱は左右・下に **18px 以上**空ける。

### ⭐ 体数を変えても壊れない並べ方

⭐ 体数を変えるたびに手で触るのをやめるため、**足りなければ写して増やし、元の占有範囲の中に
詰める**形にした。

1. いま在る器から**間隔を測る**（位置の差）
2. 新しい間隔 ＝ 元の全長 ÷（体数−1）
3. **詰めた比のぶんだけ縮める** ── 縮めないと器どうしが重なる

⚠️ **「元の場所に詰める」だけでは小さくなりすぎる。**⭐ **使える長さから逆算する**:

```
間隔 ＝ 使える長さ ÷ ((体数 − 1) + 詰まり具合)     詰まり具合 ＝ 器の高さ ÷ 元の間隔
```

⚠️ **隠れている札も数える。**自分の手番でないと技の札は出ないが、場所は変わらない。

🔴 **縮め率が1でないと、整数倍が破れる**（2026-08-30 に発覚）。器ごと `scale()` で縮めると、
`FitArtStyle` が整数倍で置いた絵がそのぶん潰れる（実測: 192px が **179px＝2.797画素/升**に
なっていた）。⭐ 基準の歩幅を詰めて**縮め率を 1.0** に戻すこと。

### ⭐ 進みは「見せてから動かす」

⚠️ 振った瞬間に駒が飛んでいたので、**何マス進んだのか目で追えなかった**。

1. 振る（Core が行き先まで動かす）
2. ⚠️ **駒は前のマスに留めて描く**
3. ⭐ 行き先のマスを光らせ、**そこを押させる**
4. ⭐ 押されたら **1マスずつ**歩く

⚠️ **歩き終わるまで次の場面へ進めない。**進めると、駒が着く前に雑魚の戦闘が始まる。

### ⭐ 手ざわり ── 予備動作 → 動作 → 余韻

| 型 | どこで使うか |
|---|---|
| **潰れて伸びる** | 駒がマスを踏むたび。⚠️ 座標を動かすだけだと「滑って」いる |
| **止める（一拍おく）** | ⭐ 関門を踏んだとき。**重い所で一拍おくと、そこが重く感じる** |
| **減衰する揺れ** | 敵に当たったとき・見つかったとき |

⚠️ **3つとも「必ず元へ戻す」。座標も寸法も持たない。**持つと、置いた位置や呼ぶ側の配置が
効かなくなる。⚠️ 画面は組み直されるので、途中で消されると**潰れたまま**の部品が残る。

| | |
|---|---|
| **短く** | 揺れは 0.28 秒。⚠️ 50〜300ms を外れると「揺れ」に見えない |
| **減衰させる** | 残りの割合を2乗して落とす。⚠️ 一定の振れ幅は機械の振動に見える |
| **層を選ぶ** | ⚠️ 揺らす相手は**組み直されない層** |

⚠️ **演出は「組み直されない層」へ出す。**盤は1マスごとに組み直されるので、浮く数字・輪・光を
盤の中に出すと、次の一歩で一緒に消える。

## 6. 字と説明

### ⭐ 字で説明せず、置き方と動きで分からせる（作者の指示）

⚠️ 説明の文を画面に置かない。⭐ 読ませるのは**絵と数**だけ。

| 書きたくなること | ⭐ 代わりに置くもの |
|---|---|
| 「のこり 6 回」 | **さいころの絵を6つ並べる。**使ったぶんは輪郭だけに変わる |
| 「壁 ＝ 攻撃」 | **上の帯と盤で同じ絵**（剣）を出す |
| 「HPが270足りない」 | **錠前の絵**と、押せない札と、暗く落とした道 |
| 「敵×2」 | **髑髏の絵を2つ**置く |
| 「どちらの道を行く？」 | **2つ並べて置くこと**そのもの |
| 「これで最後」 | 最後のさいころを**脈打たせる** |
| 「なにもない」 | **何も置かない**（無いことは、無いことで伝わる）|

⚠️ **数は字ではない。**`1,258` や `28%` は説明ではなく事実なので置いてよい。
消すのは**言い換え・言い聞かせ・手順の説明**のほう。

### ⭐ 「数えさせずに、数を見せる」

⚠️ 「出目と進むマス数が合っていない」と疑われたとき、盤を見ても確かめようが無かった。
⭐ 駒の上に**残りの歩数**を出し、1マスごとに減らした。6→5→4… と減れば、**数えなくても
合っていると分かる**。⚠️ 字で「あと3マス」と書かない ── 数だけ置く。

### ⭐ 交換を字なしで見せる

⭐ **左が払う量、右がもらう物、あいだに矢印。**⚠️ 「〇〇を払って△△を得ますか？」と書かない。
⚠️ **押さない選択も同じ大きさで置く。**小さくすると「押すのが正解」に見えて、判断そのものが消える。
⚠️ 矢印は使わなかった ── ▲（ステUP）と紛れる。

### ⚠️ 同じ枠に2つの字を重ねない

⚠️ 数と単位を**同じ枠**に置いて、位置だけずらしたら**重なった**。
⭐ 上下の帯を**分けて**置く（数は上76px・単位は下38px）。

### 字の大きさ

| | | 出所 |
|---|---|---|
| 書体 | **PixelMplus10** | `stage.css` |
| 大きさ | 🔴 **10の倍数のときだけにじまない**（8〜200px 総当たりで確認済み）| ─ |

⚠️ **これは守られていない。**実測（2026-08-30）: `size=` の 213箇所のうち、10の倍数は
**52箇所（24%）**だけ（20・30・40・50・110）。残りは 13/15/17/22/24/26/28/34… と半端。
⚠️ **検査は無い。**

🔴 **新しく置く字は 10 の倍数にする。既にあるものを一斉に直さない**（枠に収まらなくなる）。
⭐ にじみが気になった箇所から個別に直すこと。

枠の左外へ出る**。

```
戦闘画面の実測（直す前）
  器（UnitStand） x = 0.31 … 2.98
  絵（Art）       x = 0.31 … −1.35   ← 器の外。味方の列に重なっていた
```

⚠️ **スクショでは「敵が2体並んでいる」ようにしか見えなかった。**
⭐ 四隅を突き合わせて初めて分かった。

⭐ 直し方は「**反転する前に pivot をまんなかへ寄せる**」。⚠️ 寄せたぶんは位置で埋め合わせる。
⭐ **`Abs` で書く** ── 放置の帯の歩き手は元から 0.667 なので、`±1` を代入すると大きさが変わる。

### ⚠️ 縮めたら「中心」も合わせ直す（2026-08-20）

⭐ 器を写して増やすとき、**縮めたぶん位置がずれる**。pivot が左上なので、先頭の位置だけ
合わせて縮めると**全体が左（上）へ寄る**。

| 画面 | ずれ |
|---|---|
| 戦闘 | ⚠️ 中心が **437**（画面は 540）── 左に 103px |
| 放置 | ⚠️ 中心が **363**（元は 390）── 左に 27px |

**放置**は並びが意図して左寄せ（右に敵が居る構図）なので元の並びの中心を保つ。

## 7. 絵と枠が噛み合っていなかった（2026-08-29）

作者の指摘「敵の表示サイズがバラバラ」「見切れ」「もっと大きく」は、**すべて同じ1つの原因**
だった。

🔴 **描画サイズはどの画面でも同じで、不揃いだったのは枠のほう**（実測）:

| 画面 | 枠 | 64ドット種 | 16ドット種 | 症状 |
|---|---:|---:|---:|---|
| 放置帯 | 160 | 256 | 64 | 4倍差 |
