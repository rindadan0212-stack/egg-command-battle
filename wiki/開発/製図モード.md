# 製図モード（`tools/draw`）

✅ **実装しました**（2026-08-25）。「▭ 四角」「╱ 直線」「○ 円」を押すと始まる。
🔴 **2026-08-26 改訂**: モードの切り替え方を作り直した（§4・§10）── 図形の道具は
鉛筆と対等な「道具」になり、構えてもレイヤーは切り替わらない。鉛筆へ戻せば
そのまま普通に描ける。
🔴 **2026-08-26 改訂その2**: 見た目を滑らかな線からドットの並びに変えた（§3・§11）。

## 0. なぜ

> 製図モードみたいなのを入れて、CADのように図形を描いたり動かしたり、オフセットが
> 使えたりするようなものが欲しい。用途としては先に製図モードでアタリや配置を決めて
> 手書きモードで少しずつ整えていくような感じ。製図モードはCADのドットバージョン
> というイメージ。 ── 作者（2026-08-25）

⭐ 今の `tools/draw` は太さ・補助線（ガイド）・読み取りまで入った。⚠️ ガイドは
「無限に伸びる縦横1本」しか引けない ── **枠（矩形）や斜めの線を、後から動かせる
「もの」として置く**手段が無い。それを埋めるのが製図モード。

## 1. 調べたこと（2026-08-25）

### CADの本当の姿 ── 「ラスタに焼く前に、図形をオブジェクトとして持つ」

| 分類 | 主なコマンド |
|---|---|
| 描く（基本5つ） | LINE・CIRCLE・RECTANGLE・POLYLINE・HATCH |
| 直す（基本5つ） | MOVE・COPY・TRIM・**OFFSET**・ERASE |
| 直す（発展） | ROTATE・SCALE・MIRROR・EXTEND・FILLET・**ARRAY**（矩形/円形/経路の複製）|
| 精密さの土台 | 図形は**常にオブジェクト**（座標・大きさを後から数値で直せる）／スナップ（端点・中点・交点）／レイヤー |

⭐ 要点は「LINEやRECTANGLEが**絵の具ではなく駒**として置かれる」こと。置いた後に
つまんで動かせる・数値で直せる・消せる。これが「先にアタリを決めて後で手で整える」
という作者の望みとそのまま一致する。

### 先例はほぼ無い

PixiEditor が「ベクター図形×ラスタ共存」をロードマップに挙げているが、
**まだ投票段階（5票）で実装が無い。**「ドット格子×精密オブジェクト編集」は
未成熟な領域 ── コードを借りる先が無いので、ここでちゃんと設計する。

### 🔴 この用途では OFFSET が激しく軽い

CADのOFFSETは曲線の半径再計算や自己交差の失敗ケースを持つ重い処理だが、
**軸に揃った矩形・直線に限れば足し算で済む**:

```
矩形のオフセット: 外側に n ドット広げる → x-n, y-n, w+2n, h+2n（内側なら n を負に）
直交線のオフセット: 垂直方向に n ドットずらすだけ
```

UI配置（パネル・ボタン・押しどころ）はほぼ軸に揃っているので、
**CADの中でも一番「安く強い」機能から先に入れられる。**

## 2. 決めたこと（作者・2026-08-25）

| 問い | 決定 | ⚠️ 引き受けたもの |
|---|---|---|
| 置いた図形は最終的にどうなるか | ⭐ **焼かない・なぞる下敷き専用** | 最終的な絵は必ず手書きモードでなぞって作る。下敷きを動かしても手書きの線はそのまま（別レイヤー）|
| 最初に対応する図形 | ⭐ **四角・直線・円/楕円まで** | 円のOFFSET・ARRAYは計算が一段複雑（半径の再計算・格子への丸め込み）。実装コストは四角＋直線の1.5〜2倍見込み |
| 図形の置き場所 | ⭐ **専用のレイヤーを持ち、それごと保存する**（2026-08-25 追加決定） | §3 参照。当初案（§6-1 旧案「当面は保存しない」）から変更 |

## 3. 図形の持ち方 ── **専用のレイヤー**

🔴 **`state.layers` の中に、普通のレイヤーと並んで `kind: 'shapes'` の1枚を持つ。**
⭐ これにより「レイヤー一覧」に出て、名前・表示/非表示・並び順が今までの
レイヤーと同じ操作で揃う。⚠️ **図形レイヤーは1枚だけ**（重ねる意味が薄いので、
2枚目は作れないようにする）。

```js
// 普通のレイヤー（今まで通り）
{ name, opacity, visible, frames: [Uint8ClampedArray, ...] }

// 図形レイヤー（新規）
{ name, opacity, visible, kind: 'shapes', shapes: [
  { id, kind: 'rect',    x, y, w, h },       // 左上 + 大きさ（ドット・整数）
  { id, kind: 'line',    x1, y1, x2, y2 },   // 両端点
  { id, kind: 'ellipse', x, y, w, h },       // 外接する矩形（rect と同じ形）
] }
```

🔴 **なぞる下敷きは「ドットの並び」で描く**（2026-08-26 改訂・当初は `ctx.ellipse()`
等で滑らかに描いていた）。「置いたものがドットで描かれてほしい」という要望どおり、
ラスタの線/四角/丸ツールと同じ関数（`bresenhamLine`/`rectPixels`/`ellipsePixelsBox`）で
輪郭のドット座標を求め、1ドット＝1マスの `fillRect` で描く。実際にラスタ化したときと
**寸分違わぬ形**が最初から見える。焼かないので、精度が要るのは見た目だけ ──
データは今までどおり `x,y,w,h` 等の数値のまま（ドット近似は描画のたびに再計算する
だけで、図形そのものはずっと自由に変形・移動できる）。

### 🔴 保存 ── 触る箇所は3つだけ（実物のコードで確認済み）

`makeWorkPayload()` は**作品の内部保存（localStorage）と `.pixelizer.json` の書き出しの
両方に使われる唯一の関数**（`saveWorkNow`・ファイル書き出し、どちらもこれを呼ぶ）。
`state.layers` をそのまま map しているので、**図形レイヤーをここに加えるだけで
両方の保存に自動で乗る**（新しい保存経路を作らない）。

| 触る場所 | 何をするか |
|---|---|
| `compositeFrame()` | 先頭で `if (layer.kind === 'shapes') continue;`（合成に混ぜない・焼かない） |
| `refreshActiveCel()` | 図形レイヤーがアクティブなら `state.pixels = null` にして抜ける（`.frames` が無い） |
| `makeWorkPayload()` | 図形レイヤーは `frames` の代わりに `shapes` を書き出す |

⚠️ **`sim import-screen`（C#側）は何もしなくても壊れない。**`frames` が無い層は
今の実装でも「コマが1つも無い」として素通りする。⭐ ただし紛らわしいので、
`ImportScreen.cs` に `kind == "shapes"` を見て**分かりやすい一言**で飛ばす分岐を足す
（警告ではなく「製図の下敷きなので取り込みません」という案内）。

## 4. モードの切り替え ── 🔴 **図形の道具そのものが1つの道具（2026-08-26 改訂）**

⚠️ **旧設計（「図形レイヤーを選ぶこと自体がモード」）は撤回した。**
「製図モードでもドットで書きたい」という要望どおり、道具を構えるたびに
レイヤーごと切り替わって鉛筆が使えなくなるのは実用上ネックだった
（詳しい経緯は §10）。今は鉛筆・消し・投げ輪などと**対等な道具の1つ**として
図形の道具（四角・直線・円・選ぶ）を `state.tool` に載せている。

| | やること |
|---|---|
| 四角・直線・円・選ぶ を押す | `state.tool` がその道具になる（図形レイヤーが無ければ**その場で作るだけ**で、今のレイヤーは離れない）|
| キャンバスを押す（図形の道具のとき） | 図形を選ぶ・掴んで動かす・新しく置く |
| 鉛筆・消し等へ戻す | 元のラスタレイヤーのまま普通に描ける。**選んでいた図形はそのまま覚えている**ので、また図形の道具に戻せば続きから触れる |
| 図形（見た目） | どの道具・どのレイヤーを選んでいても、図形レイヤーが**表示 ON なら常に**下敷きとして見える（`layer.visible` だけで判定・レイヤー選択とは無関係）|

⭐ レイヤー欄で図形レイヤーそのものを直に選ぶことも変わらずできる
（並べ替え・表示切替・不透明度・削除のため）。その場合は `state.pixels` が
無い＝描く先が無いので、道具を自動で「選ぶ」に合わせてハンドルとインスペクタを
出す（`switchLayer` 内）。この状態は今までどおり鉛筆では描けない
（描く場所が物理的に無いので、これは残る自然な制約）。

## 5. できること

### 置く
図形の道具（四角／直線／円）を選び、キャンバスをドラッグして置く。
⭐ **格子・ガイド・他の図形の端点/中点/中心/接点へスナップ**する
（種類ごとに ON/OFF・くわしくは §6-3）。

### 選ぶ・数値で直す
図形を押すと選ばれ、`x, y, w, h`（線なら `x1,y1,x2,y2`）を**数値で**打ち直せる。
⭐ 既にある読み取り欄（実測を出す場所）の隣に出す ── 「見えている数」と
「打ち込む数」を離さない。

### 動かす（MOVE）
本体をドラッグで動かす（スナップつき）。⭐ 選んでいる間は矢印キーで1ドット単位の
微調整（Shift+矢印で目盛りの間隔ぶん）── 既存の読み取り・目盛り機能とそのまま噛み合う。

### オフセット
選んだ図形に対して、ドット数を打つと**新しい図形として**外側/内側にずらしたものを作る
（元の図形は残す ── 本物のCADのOFFSETと同じ約束）。⭐ 「外枠と、内側の安全域」を
両方なぞりたいときに、元を消さずに済む。

### 複製して並べる（ARRAY・矩形のみ）
列数・行数・間隔（ドット）を打つと、その並びで複製する。
⭐ この作品の骨組みが持つ `repeat=`（`cols=`/`gap=`/`rows=`）と**同じ考え方**
── BOXの升目やアイコン列のアタリを、実装前に目で確かめられる。

### 消す
選んで Delete。⭐ **図形レイヤーがアクティブなときだけ**この経路が働く
（手書きモードの「選択→Delete」＝ドットを消す、とは自然に分かれる ── モードの
分岐そのものが「今アクティブなのはどちらの種類のレイヤーか」で決まるため）。

### ✅ 6-3. スナップの種類（解決済み・2026-08-25）

> スナップは複数個所設定したくて、例えば中心だったり、角、接点など。 ── 作者

⭐ **1種類に絞らず、CADの「実行時オブジェクトスナップ」と同じ形にする**
── 種類ごとに ON/OFF を切り替えられ、有効なものの中から**一番近い1点**へ吸い付く
（「複数候補を出して選ばせる」のではなく、「候補の母集団を種類で絞れる」）。

#### 図形の種類ごとに出る点

| 種類 | 矩形 | 直線 | 円・楕円 |
|---|---|---|---|
| **端点** | 4隅 | 両端 | ── （楕円に端点は無い）|
| **中点** | 4辺それぞれの中点 | 中点 | ── |
| **中心** | 対角線の交点 | ── （線には無い。中点と同じ位置になるため省く）| 外接する矩形の中心 |
| **接点** | ── | ── | ⭐ **外接する矩形と接する4点**（上下左右の頂点）|

⚠️ **「接点」は円周上の好きな点に吸い付く連続的なものではなく、
この4点に固定する。**⚠️ 連続スナップ（カーソルに一番近い円周上の点、を毎回計算）は
狙った所へ正確に置きにくく、この作品の「数値で決まる」という一貫性からも外れるため
採らない。

⚠️ 格子・ガイドも同じ枠組みの中の「種類」として扱う（今までの案と統合）。

#### 種類の切り替え

製図モードの道具欄に、種類ごとの小さな釦を並べる:

```
[格子] [ガイド] [端点] [中点] [中心] [接点]
```

⭐ **既定は全部 ON。**候補が増えても「一番近い1点」を選ぶだけなので、
外れる方向には働きにくい（大きな矩形の中心が、辺の近くをドラッグしているときに
誤って選ばれることは起きにくい ── 近いものが勝つため）。

#### 見分け方

⭐ 吸い付いた点に、**種類ごとに違う小さな印**を出す（CADにならう）:
`□ 端点` `△ 中点` `○ 中心` `◇ 接点` `+ 格子` `┆ ガイド`。
「何に吸い付いたか」を見た目で答えられるようにする ── 数字だけだと分かりにくい。

## 7. 見送ったもの（CADにあるが、この用途では要らない）

| CADの機能 | 見送る理由 |
|---|---|
| TRIM/EXTEND（線を切る/伸ばす） | UI配置は矩形どうしの重なりで済む。線を交点で切る場面が少ない |
| FILLET/CHAMFER（角丸め） | ドット絵の角丸は別の描き方（絵自体で表現）がすでにある |
| 円形・経路のARRAY | 矩形の並びだけで大半をカバーできる |
| 交点スナップ（線と線・線と円が交わる点） | §6-3 の6種類（格子・ガイド・端点・中点・中心・接点）は「図形1つが持つ決まった点」で済むが、交点は**2つの図形の組み合わせごとに計算**が要る ── 費用が一段上がる。要ると分かってから足す |
| 連続スナップ（円周上の好きな点に吸い付く） | §6-3 で明示的に不採用（接点は4点に固定） ── 数値で決まる一貫性を優先 |
| ROTATE（回転） | UI要素はほぼ軸に揃っている。回転が要る場面が今のところ無い |

## 8. 実装して見つかった罠（2026-08-25）

### 🔴 `state.pixels` が「作品があるか」の判定に**16箇所**流用されていた

設計時点で見えていたのは3箇所（`compositeFrame`・`refreshActiveCel`・`makeWorkPayload`）
だったが、実装しながら実物のコードを追ったところ、**保存・書き出し・プレビュー・ズーム・
できあがり欄の表示切替**まで `state.pixels`（＝「ラスタが今描ける状態か」）で判定していた。

図形レイヤーがアクティブだと `state.pixels` は null になる（§4 の要）ので、直さないと
**製図モードに入っただけでこれらが軒並み止まっていた。**

🔴 一番重大だったのは `saveWorkNow()` と `pagehide` のオートセーブ。「それごと保存させたい」
という要望の核心を壊すバグを、実装の途中で見つけて直した。

⭐ `hasArtwork()`（`state.layers.length > 0`）を新設し、「作品が在るか」を
`state.pixels` から分離した。

### 🔴 `state.draft.guideMode` が localStorage 経由で永続化されていた

「見え方の好み」を丸ごと `state.draft` から `JSON.stringify` して保存していたため、
**「縦ガイドを置く」モードのまま閉じると、次に開いたときも同じモードのまま**だった
── 最初のクリックが鉛筆ではなくガイド配置に化ける。しかも気づきにくい（描けないのではなく
違うものが起きる）。

⭐ 覚えるものを `DRAFT_PERSIST_KEYS`（`center`/`readout`/`major`/`guides`/`snapKinds`）に
明示的に絞り、`guideMode`/`shapeTool`/`selectedShapeId` のような「今どう触っているか」の
一時的な状態は保存対象から外した。

### `renderEditor`/`drawDraftOverlay` の入口ガードも同じ穴

`if (!state.pixels) return;` が2箇所にあり、製図モードだと**下敷き（格子・中心線・
ガイド・図形）ごと描かれなくなる**ところだった。「作品が0件か」（`state.layers.length`）
での判定に直した。

## 10. モードをレイヤーから道具へ切り離した（2026-08-26）

### なぜ

> 製図モードでもドットで書けるようにしたいんだけどできないかな？

§4 の元の設計（図形レイヤーを選ぶこと＝製図モード）は、四角・直線・円のどれかを
押すたびに `state.currentLayer` を図形レイヤーへ強制で切り替えていた。図形レイヤーは
`.frames` を持たないので `state.pixels` が null になり、**鉛筆・消しゴムが物理的に
使えなくなる** ── 下敷きを置いてすぐ横でなぞりたいだけなのに、毎回レイヤー欄まで
戻ってラスタ層を選び直す往復が発生していた。

### 何を変えたか

- `state.tool` に `shapeRect`/`shapeLine`/`shapeEllipse`/`shapeSelect` の4値を追加。
  鉛筆・消し・投げ輪・`movelayer` と同じ「道具」として扱う（`setActive()` 経由）。
- 四角・直線・円・選ぶ ボタンは、図形レイヤーが無ければ**その場で作るだけ**
  （`addShapesLayer(false)` ── レイヤーは切り替えない）で、`setActive()` を呼ぶだけになった。
  **今のラスタレイヤーを離れない。**
- `pointerdown` の横取り条件を「今のレイヤーが図形レイヤーか」から
  「図形の道具を構えているか（`SHAPE_EDIT_TOOLS.includes(state.tool)`）」に変更。
  ただし**レイヤー欄で図形レイヤーを直に選んだ場合**（`state.pixels` が無い）は
  道具の値に関わらず引き続き横取りする OR 条件を残した ── でないと
  「押しても何も起きない」バグになる（`state.pixels` が null な状態で鉛筆の
  処理へ落ちるとクラッシュする）。
- 図形の見た目（`drawShapesLayer`）・選択ハンドル・インスペンタ・Delete キーの
  有効条件も、すべて「今のレイヤー」基準から「今の道具」基準に揃えた。
- `switchLayer()` に、レイヤー欄で図形レイヤーを直に選んだときだけ道具を
  `shapeSelect` に自動で合わせる分岐を追加（ハンドル・インスペクタがすぐ出るように）。
  **逆方向（ラスタ層へ戻すとき）は道具を強制で戻さない** ── ここを対称にすると
  「道具を構えたまま鉛筆と行き来する」という今回の変更の意味が消える。
- 図形の選択（`state.draft.selectedShapeId`）は道具を切り替えても**そのまま残す**
  （鉛筆へ戻っても消さない）。Delete キーは道具ゲートで守っているので、
  選択が残っていても鉛筆使用中に誤爆しない。むしろ「また図形の道具に戻せば
  続きから触れる」という連続性の方を優先した。

### 検証（実ブラウザ・Playwright・2026-08-26）

- 「四角」を押しても `state.currentLayer` が動かず、`state.pixels` が null に
  ならないことを確認
- 図形を1つ配置 → 鉛筆に切り替え（レイヤー欄は触らない）→ 実際にドットが
  塗れることを確認 → 図形はそのまま残っていることを確認
- レイヤー欄で図形レイヤーを直に選ぶと、道具が自動で「選ぶ」になり
  インスペクタ・ハンドルが出ること、Delete キーで選択中の図形が消えることを確認
- `state.tool='pencil'` のまま `state.currentLayer` だけ図形レイヤーという
  矛盾した状態を人為的に作ってポインタ操作しても、例外を投げず安全に
  図形側の処理（選ぶ/何もしない）へ落ちることを確認（OR 条件の安全網）
- Undo/Redo が図形操作・ラスタ描画をまたいでも壊れないことを確認

## 11. 見た目を「ドットの並び」に変えた（2026-08-26）

### なぜ

> 図形で書いたものがドットで書かれてほしい。今は製図すると細い線がおかれるだけ
> なので自由に変形、移動できるドット線を製図モードでは置ける感じ。

`ctx.rect()`/`ctx.moveTo`+`lineTo`/`ctx.ellipse()` で描いていたので、ズームしても
線幅が一定の**滑らかな細い線**にしかならず、ドット絵の下敷きとして「これをなぞると
どんな形になるか」が直感的に読めなかった。

### 何を変えたか

- `shapeOutlineDots(s)` を新設。図形の輪郭を、**ラスタの線/四角/丸ツールと全く同じ
  関数**（`bresenhamLine`/`rectPixels`（`filled=false`）/`ellipsePixelsBox`
  （`filled=false`））でドット座標の並びに変換する。
- `drawShapesLayer()` は `ctx.stroke()` をやめ、輪郭の各ドットを
  `ctx.fillRect(devX(x), devY(y), 1セル分, 1セル分)` で塗る。**1ドット＝1マス**、
  ズームすればちゃんと大きな正方形になる ── 本物のラスタと同じ縮尺。
- 色分け（未選択＝緑透過・選択中＝橙）は維持。破線（`setLineDash`）による
  未選択/選択の書き分けはドット塗りには合わないのでやめ、色だけで区別する。
- 図形そのもののデータ（`x,y,w,h`/`x1,y1,x2,y2`）は一切変えていない ──
  **見た目の計算だけ**を毎フレーム再実行する形なので、自由変形・移動・
  スナップ・オフセット・ARRAY は今までどおりそのまま使える。

### 検証（実ブラウザ・Playwright・2026-08-26）

- `shapeOutlineDots()` の返り値を実際の `rectPixels`/`bresenhamLine`/
  `ellipsePixelsBox` の出力と突き合わせ、矩形の枠・斜め線のジグザグ・楕円の
  輪郭がそれぞれ正しいドット列になることを確認
- ズームしたスクリーンショットで、直線が実際の鉛筆と同じ階段状のドットで
  見えることを目視確認
