# 製図モード（`tools/draw`）

⚠️ **これは設計です。まだ実装していません。**

## 0. なぜ

> 製図モードみたいなのを入れて、CADのように図形を描いたり動かしたり、オフセットが
> 使えたりするようなものが欲しい。用途としては先に製図モードでアタリや配置を決めて
> 手書きモードで少しずつ整えていくような感じ。製図モードはCADのドットバージョン
> というイメージ。 ── 作者（2026-08-25）

⭐ 今の `tools/draw` は太さ・補助線（ガイド）・読み取りまで入った。⚠️ ガイドは
「無限に伸びる縦横1本」しか引けない ── **枠（矩形）や斜めの線を、後から動かせる
「もの」として置く**手段が無い。それを埋めるのが製図モード。

## 1. 調べたこと（2026-08-25）

### CADの本当の姿 ── 「ラスタに焼く前に、図形をオブジェクトとして持つ」

| 分類 | 主なコマンド |
|---|---|
| 描く（基本5つ） | LINE・CIRCLE・RECTANGLE・POLYLINE・HATCH |
| 直す（基本5つ） | MOVE・COPY・TRIM・**OFFSET**・ERASE |
| 直す（発展） | ROTATE・SCALE・MIRROR・EXTEND・FILLET・**ARRAY**（矩形/円形/経路の複製）|
| 精密さの土台 | 図形は**常にオブジェクト**（座標・大きさを後から数値で直せる）／スナップ（端点・中点・交点）／レイヤー |

⭐ 要点は「LINEやRECTANGLEが**絵の具ではなく駒**として置かれる」こと。置いた後に
つまんで動かせる・数値で直せる・消せる。これが「先にアタリを決めて後で手で整える」
という作者の望みとそのまま一致する。

### 先例はほぼ無い

PixiEditor が「ベクター図形×ラスタ共存」をロードマップに挙げているが、
**まだ投票段階（5票）で実装が無い。**「ドット格子×精密オブジェクト編集」は
未成熟な領域 ── コードを借りる先が無いので、ここでちゃんと設計する。

### 🔴 この用途では OFFSET が激しく軽い

CADのOFFSETは曲線の半径再計算や自己交差の失敗ケースを持つ重い処理だが、
**軸に揃った矩形・直線に限れば足し算で済む**:

```
矩形のオフセット: 外側に n ドット広げる → x-n, y-n, w+2n, h+2n（内側なら n を負に）
直交線のオフセット: 垂直方向に n ドットずらすだけ
```

UI配置（パネル・ボタン・押しどころ）はほぼ軸に揃っているので、
**CADの中でも一番「安く強い」機能から先に入れられる。**

## 2. 決めたこと（作者・2026-08-25）

| 問い | 決定 | ⚠️ 引き受けたもの |
|---|---|---|
| 置いた図形は最終的にどうなるか | ⭐ **焼かない・なぞる下敷き専用** | 最終的な絵は必ず手書きモードでなぞって作る。下敷きを動かしても手書きの線はそのまま（別レイヤー）|
| 最初に対応する図形 | ⭐ **四角・直線・円/楕円まで** | 円のOFFSET・ARRAYは計算が一段複雑（半径の再計算・格子への丸め込み）。実装コストは四角＋直線の1.5〜2倍見込み |
| 図形の置き場所 | ⭐ **専用のレイヤーを持ち、それごと保存する**（2026-08-25 追加決定） | §3 参照。当初案（§6-1 旧案「当面は保存しない」）から変更 |

## 3. 図形の持ち方 ── **専用のレイヤー**

🔴 **`state.layers` の中に、普通のレイヤーと並んで `kind: 'shapes'` の1枚を持つ。**
⭐ これにより「レイヤー一覧」に出て、名前・表示/非表示・並び順が今までの
レイヤーと同じ操作で揃う。⚠️ **図形レイヤーは1枚だけ**（重ねる意味が薄いので、
2枚目は作れないようにする）。

```js
// 普通のレイヤー（今まで通り）
{ name, opacity, visible, frames: [Uint8ClampedArray, ...] }

// 図形レイヤー（新規）
{ name, opacity, visible, kind: 'shapes', shapes: [
  { id, kind: 'rect',    x, y, w, h },       // 左上 + 大きさ（ドット・整数）
  { id, kind: 'line',    x1, y1, x2, y2 },   // 両端点
  { id, kind: 'ellipse', x, y, w, h },       // 外接する矩形（rect と同じ形）
] }
```

⭐ **なぞる下敷きは滑らかに描く**（`ctx.ellipse()` 等・ジャギーなドット近似ではない）。
焼かないと決めたので、ラスタ化の精度を気にする必要が無い ── 目で追いやすい方を選ぶ。

### 🔴 保存 ── 触る箇所は3つだけ（実物のコードで確認済み）

`makeWorkPayload()` は**作品の内部保存（localStorage）と `.pixelizer.json` の書き出しの
両方に使われる唯一の関数**（`saveWorkNow`・ファイル書き出し、どちらもこれを呼ぶ）。
`state.layers` をそのまま map しているので、**図形レイヤーをここに加えるだけで
両方の保存に自動で乗る**（新しい保存経路を作らない）。

| 触る場所 | 何をするか |
|---|---|
| `compositeFrame()` | 先頭で `if (layer.kind === 'shapes') continue;`（合成に混ぜない・焼かない） |
| `refreshActiveCel()` | 図形レイヤーがアクティブなら `state.pixels = null` にして抜ける（`.frames` が無い） |
| `makeWorkPayload()` | 図形レイヤーは `frames` の代わりに `shapes` を書き出す |

⚠️ **`sim import-screen`（C#側）は何もしなくても壊れない。**`frames` が無い層は
今の実装でも「コマが1つも無い」として素通りする。⭐ ただし紛らわしいので、
`ImportScreen.cs` に `kind == "shapes"` を見て**分かりやすい一言**で飛ばす分岐を足す
（警告ではなく「製図の下敷きなので取り込みません」という案内）。

## 4. モードの切り替え ── 🔴 **図形レイヤーを選ぶこと自体がモード**

⭐ **新しいモード切り替えボタンを作らない。**「レイヤー一覧」で図形レイヤーを
アクティブにすれば製図モード、普通のレイヤーに戻せば手書きモードに戻る
── レイヤー切り替えは既にある操作なので、覚えることが増えない。

| | 図形レイヤーがアクティブ（製図モード） | 普通のレイヤーがアクティブ（手書きモード） |
|---|---|---|
| キャンバスを押す | 図形を選ぶ・掴んで動かす・新しく置く | 鉛筆・消しゴムで描く |
| 鉛筆・消しゴム | 使わない（`state.pixels` が無いので自然に描けない）| そのまま |
| 他のレイヤーの図形/絵 | **なぞる下敷きとして見えるだけ**（触れない）| 同左 |

⚠️ 既存の `pointerdown` 横取り（ガイド配置と同じ場所）に、
「今のアクティブ層が `kind==='shapes'` か」を見る分岐を1つ足す形になる
（「通常の描画より先に奪う」という決め方を壊さない）。

## 5. できること

### 置く
図形の道具（四角／直線／円）を選び、キャンバスをドラッグして置く。
⭐ **格子・ガイド・他の図形の端点/中点/中心/接点へスナップ**する
（種類ごとに ON/OFF・くわしくは §6-3）。

### 選ぶ・数値で直す
図形を押すと選ばれ、`x, y, w, h`（線なら `x1,y1,x2,y2`）を**数値で**打ち直せる。
⭐ 既にある読み取り欄（実測を出す場所）の隣に出す ── 「見えている数」と
「打ち込む数」を離さない。

### 動かす（MOVE）
本体をドラッグで動かす（スナップつき）。⭐ 選んでいる間は矢印キーで1ドット単位の
微調整（Shift+矢印で目盛りの間隔ぶん）── 既存の読み取り・目盛り機能とそのまま噛み合う。

### オフセット
選んだ図形に対して、ドット数を打つと**新しい図形として**外側/内側にずらしたものを作る
（元の図形は残す ── 本物のCADのOFFSETと同じ約束）。⭐ 「外枠と、内側の安全域」を
両方なぞりたいときに、元を消さずに済む。

### 複製して並べる（ARRAY・矩形のみ）
列数・行数・間隔（ドット）を打つと、その並びで複製する。
⭐ この作品の骨組みが持つ `repeat=`（`cols=`/`gap=`/`rows=`）と**同じ考え方**
── BOXの升目やアイコン列のアタリを、実装前に目で確かめられる。

### 消す
選んで Delete。⭐ **図形レイヤーがアクティブなときだけ**この経路が働く
（手書きモードの「選択→Delete」＝ドットを消す、とは自然に分かれる ── モードの
分岐そのものが「今アクティブなのはどちらの種類のレイヤーか」で決まるため）。

⭐ **専用のレイヤーとして `state.layers` に持ち、`makeWorkPayload()` に自動で乗せる**
（§3）。作品ごとに正しく分かれる（レイヤーは元から作品＝1つの `.pixelizer.json` に
閉じているため、「別の絵を開いたら前の下敷きが出てくる」という旧案の懸念は起きない）。

### ✅ 6-2. 図形どうしの重なりと前後関係（解決済み・2026-08-25・推奨案どおり）

⭐ **後から置いたものが手前**（今の骨組み・レイヤーと同じ約束）。
⚠️ 並べ替え（前面へ/背面へ）は最初は無し ── 要ると分かってから。

### ✅ 6-3. スナップの種類（解決済み・2026-08-25）

> スナップは複数個所設定したくて、例えば中心だったり、角、接点など。 ── 作者

⭐ **1種類に絞らず、CADの「実行時オブジェクトスナップ」と同じ形にする**
── 種類ごとに ON/OFF を切り替えられ、有効なものの中から**一番近い1点**へ吸い付く
（「複数候補を出して選ばせる」のではなく、「候補の母集団を種類で絞れる」）。

#### 図形の種類ごとに出る点

| 種類 | 矩形 | 直線 | 円・楕円 |
|---|---|---|---|
| **端点** | 4隅 | 両端 | ── （楕円に端点は無い）|
| **中点** | 4辺それぞれの中点 | 中点 | ── |
| **中心** | 対角線の交点 | ── （線には無い。中点と同じ位置になるため省く）| 外接する矩形の中心 |
| **接点** | ── | ── | ⭐ **外接する矩形と接する4点**（上下左右の頂点）|

⚠️ **「接点」は円周上の好きな点に吸い付く連続的なものではなく、
この4点に固定する。**⚠️ 連続スナップ（カーソルに一番近い円周上の点、を毎回計算）は
狙った所へ正確に置きにくく、この作品の「数値で決まる」という一貫性からも外れるため
採らない。

⚠️ 格子・ガイドも同じ枠組みの中の「種類」として扱う（今までの案と統合）。

#### 種類の切り替え

製図モードの道具欄に、種類ごとの小さな釦を並べる:

```
[格子] [ガイド] [端点] [中点] [中心] [接点]
```

⭐ **既定は全部 ON。**候補が増えても「一番近い1点」を選ぶだけなので、
外れる方向には働きにくい（大きな矩形の中心が、辺の近くをドラッグしているときに
誤って選ばれることは起きにくい ── 近いものが勝つため）。

#### 見分け方

⭐ 吸い付いた点に、**種類ごとに違う小さな印**を出す（CADにならう）:
`□ 端点` `△ 中点` `○ 中心` `◇ 接点` `+ 格子` `┆ ガイド`。
「何に吸い付いたか」を見た目で答えられるようにする ── 数字だけだと分かりにくい。

## 7. 見送ったもの（CADにあるが、この用途では要らない）

| CADの機能 | 見送る理由 |
|---|---|
| TRIM/EXTEND（線を切る/伸ばす） | UI配置は矩形どうしの重なりで済む。線を交点で切る場面が少ない |
| FILLET/CHAMFER（角丸め） | ドット絵の角丸は別の描き方（絵自体で表現）がすでにある |
| 円形・経路のARRAY | 矩形の並びだけで大半をカバーできる |
| 交点スナップ（線と線・線と円が交わる点） | §6-3 の6種類（格子・ガイド・端点・中点・中心・接点）は「図形1つが持つ決まった点」で済むが、交点は**2つの図形の組み合わせごとに計算**が要る ── 費用が一段上がる。要ると分かってから足す |
| 連続スナップ（円周上の好きな点に吸い付く） | §6-3 で明示的に不採用（接点は4点に固定） ── 数値で決まる一貫性を優先 |
| ROTATE（回転） | UI要素はほぼ軸に揃っている。回転が要る場面が今のところ無い |
